352: // ── 派生关系注册表（数据驱动，吸收 Accio 的 logicalStoreKey 分组语义）──────
353: 
354: /**
355:  * 平台间的**登录态派生关系**及其级联影响，单一真源。
356:  *
357:  * ## 为什么要把关系从代码里提出来
358:  *
359:  * 改造前，「淘宝登录 → 生意参谋可用」「淘宝登录 → 闲鱼自动派生」这两件事的真相
360:  * 分散在三处：`CREDENTIAL_PLATFORM`（凭证落哪）、`SHARED_LOGIN_PLATFORM`（谁能独立登录）、
361:  * 以及 `ensureXianyuFromTaobao()` 里的硬编码判断。
362:  *
363:  * 后果是**断开一个账号时无法预知会波及谁**：用户删掉淘宝账号，生意参谋系与闲鱼的
364:  * 凭证行会变成孤儿（`credential_platform` 仍指向已不存在的 taobao），
365:  * 直到下次跑技能才报「未绑定」，用户完全不知道原因。
366:  *
367:  * Accio 用 `logicalStoreKey` 把多区域/多子店收敛成一个逻辑店铺，并支持
368:  * `managedShopDisconnectGroup` 按逻辑店铺**整组断开** —— 正是为了解决同一类问题。
369:  *
370:  * 本注册表把这层关系显式化，从而支持：
371:  *   1. `derivedPlatformsOf(platform)` —— 断开会波及谁（用于删前提示与级联清理）
372:  *   2. `derivationChainFor(platform)` —— 该平台的完整上游链（用于引导文案）
373:  *
374:  * ## 字段语义
375:  *
376:  * - `owner`：登录态的**所有者**平台（用户应当去登录的那个）
377:  * - `derived`：依赖 owner 登录态的**下游**平台
378:  * - `keepsOwnRow`：下游是否保留独立凭证行
379:  *     · `false`（生意参谋系）—— 凭证层直接复用 owner 的 Cookie，无独立行
380:  *     · `true`（闲鱼）—— 必须保留独立行（goofish 域 Cookie 要落在自己的条目上），
381:  *       但由 owner 登录成功后自动派生；账号页隐藏该行
382:  * - `note`：面向用户的一句话解释（引导文案与删除提示复用）
383:  */
384: export interface DerivationRelation {
385:   owner: string
386:   derived: string
387:   keepsOwnRow: boolean
388:   note: string
389: }
