# 货品分层诊断

> 由参谋长平台分析包「货品分层诊断」（playbook v1.2.0）转换而来的技能：
> 原「数据准备 / 引用知识 / AI 分析 / 报告」四类节点分别对应本文 §1 / §2 / §3 / §4。

## 前置条件

- 已取得商品经营表现表（`sycm.item_top`，必需）；商品推广数据（`sycm.alimama_item_promotion`，可选，缺失时推广维度标 Unknown。
- 用户指定了分析周期；未指定时先确认。
- 样本量门限：在架商品 < 30 个时，分层结论降级为"初步观察"，不得据此调整资源。

## 工作流

1. **锁定数据**：冻结 `item_top`（及推广表，如有）为本次证据。
2. **按贡献分层**：以经营贡献（销售额/利润贡献）为核心款/成长款/潜力款/观察款/低效退出款五层。
3. **按质量校验**：结合经营质量（退款率/评价/转化）与成长潜力（趋势/增速）修正分层。
4. **风险标注**：识别"高价值但存在经营风险"的商品（高销但高退款/高推广依赖）。
5. **输出资源策略**：每层的资源分配建议——保护/投入/培养/观察/退出，附关键证据。
6. **报告**：产出货盘结构诊断与资源分配策略，生成前须用户确认。

## 错误处理

- 推广数据缺失：推广维度全部标 `[unknown]`，不参与分层计算，仅做只读展示。
- 商品数 < 30：输出"初步观察"并说明样本不足，不给出资源调整建议。
- 同款多链接（重复铺货）：先聚合到款式级再分层，避免同款占多个层位。
- 退款/评价数据过期：标注数据时点，分层结论相应标注时效风险。

### 取数规则

- 输出视图口径：周期汇总（period_summary）；时间窗口与本次分析口径一致，层级迁移判断需两个可比周期。
- 通过插件账号工具 / 取数网关读取已绑定店铺的授权数据；先确认商品身份（ID + 标题）与样本规模，再进入分析。
- 推广数据缺失不阻断主体分层，但需在报告中说明并按 `missing_evidence` 记录。
- 缺失、未知、未采集都不等于 0；只有上游明确返回 0 才能写「零成交」。

## 3. AI 分析要求

### 判断顺序

1. 先确认商品身份、样本规模和数据完整性，判断当前证据是否足以进行商品分层。
2. 先看商品对店铺的实际经营贡献，再看成交质量和经营风险。
3. 再判断成长潜力，区分「已经形成增长结果」「只有正向信号」和「仍缺乏验证」的商品。
4. 综合经营贡献、经营质量、成长潜力和样本成熟度确定商品当前层级。
5. 将商品层级与风险状态分开判断，再检查整个货盘的层级结构是否健康。
6. 证据不足时降低结论强度或进入待验证，不强行完成分层。

### 必须回答的问题

- 哪些商品属于核心款、成长款、潜力款、观察款或低效退出款？
- 每个商品为什么属于当前层级，最关键的判断依据是什么？
- 哪些高价值商品同时存在经营风险，不能因为分层较高而忽略？
- 当前货盘是否存在核心款过度集中、成长梯队不足或低效商品占用资源的问题？
- 哪些商品证据不足无法可靠分层，或需要进入专项诊断继续判断？

### 证据要求

- 具体商品分层必须有明确商品身份和商品级经营数据；**店铺汇总数据不能用于推断具体商品层级**。
- 核心款必须有较大且相对稳定的实际经营贡献，不能只依据单日高销售判断。
- 成长款和潜力款必须有真实的成交或正向经营信号；不能因为是新品或计划重点推广就认定有潜力。
- 低效退出款必须有「经过合理经营机会后仍持续低效」的证据；新品、小样本或短周期表现差不能直接淘汰。
- 商品层级迁移必须有可比周期证据；只有当前数据时只判断当前层级。
- 缺少关键证据时必须记录 `missing_evidence`，不得自行补造阈值、趋势、商品状态或经营原因。

### 期望输出

- 能够可靠判断的商品分层结果及每个商品的核心分层依据。
- 商品经营层级与风险状态分别给出，识别高价值但存在风险的商品。
- 核心款、成长款、潜力款中需要保护、培养或继续验证的重点商品。
- 观察款、低效退出款中需要继续验证、减少资源或考虑退出的商品。
- 货盘整体结构判断：核心款集中、成长梯队不足、低效资源占用等主要问题。
- 无法可靠分层的商品、`missing_evidence` 及需进入专项诊断的对象。

## 4. 报告

- 标题：**货品分层诊断报告**
- 格式：HTML；大纲固定为 5 节：
  1. 货盘分层总览
  2. 重点商品分层与依据
  3. 商品风险与异常
  4. 货盘结构问题
  5. 资源策略与专项下钻
- 输出契约：
  - 必须覆盖所有 finding、evidence、knowledge_basis 和 recommendation，结论必须附带证据与行动建议。
  - 运行 ID、步骤 ID、方法 ID、节点 ID、finding / evidence / recommendation 等内部追踪 ID 只保留在 `data-*` 属性中，不进正文。
  - 商品 ID 等业务标识按上游结果正常展示；上游已返回名称时，每次出现业务 ID 都必须同时展示对应名称。
  - 报告需**人工确认后**再定稿。

## 5. 禁止与边界

以 `knowledge/product_layering_rules.md` 的「禁止与边界」章节为准，核心几条：

- 不得仅按销售额 / 支付金额 / GMV 排名直接完成分层。
- 不得使用固定数值阈值作为所有店铺通用的分层标准（除非店铺配置或明确业务规则已提供）。
- 不得把商品层级和商品健康状态混为一谈。
- 不得把运营主观意愿、计划重点推广当作成长潜力证据。
- 不得将行业经验、类目经验或平台常识描述为当前商品已发生的事实。
- 本技能只判断商品经营角色与资源策略；发现具体异常后应进入对应单品专项诊断，不用分层解释具体根因。

## 证据分级（输出结论前必读）

本技能输出任何"结论"前，先按**证据四分级**标注级别（Observed 直采 / Calculated 计算 /
Proxy 代理推断 / Unknown 未知），并遵守五条禁止推断——尤其是：
**sycm/万相台指数一律标 Proxy，不得当绝对量**；**Unknown 不得当 0 参与平均**。

完整分级表、五条禁止推断与国内场景注释见 [references/evidence-rules.md](references/evidence-rules.md)。
