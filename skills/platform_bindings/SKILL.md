# 平台账号绑定查询

## 什么时候用

- 用户问「绑定了哪些平台 / 店铺 / 账号」
- 任务需要淘宝、生意参谋、抖店等 **已绑定凭证**，要先确认是否已绑定
- 向用户说明当前智能体可用的电商账号

### 不应使用

- 需要 **新增或修改** 平台连接 → 引导用户在控制台 **平台连接** 页操作（桌面版登录）
- 只是拉取 Cookie 调接口 → 用业务 skill 自带的凭证逻辑，不必先列绑定（除非要先确认）

## 查询方式

**直接调用内置工具**（推荐，无需 shell）：

```
get_platform_bindings()
```

指定其他智能体时传 `agent_id`；默认使用 **当前会话的智能体 ID**。

## 响应含义

工具输出首行固定为 `agent_id: …`，表示本次查询的是哪个智能体（避免会话智能体与刚绑定的智能体不一致时误判）。

| 字段 | 含义 |
|------|------|
| `agent_id` | 本次查询的智能体 ID |
| `platform` | 平台键（如 `taobao`、`sycm`、`fxg`） |
| `platform_name` | 展示名（如「淘宝网」） |
| `display_label` | 登录信息（昵称或 account_id） |
| `status` | `valid` / `expired` / `none`（缓存或键检查结果） |

## 工作流

```
1. 调用 get_platform_bindings()（用户刚改过绑定后必须重新调用，勿复述历史）
2. 核对首行 agent_id 是否为用户正在操作的智能体
3. 无绑定 → 说明未绑定，引导去「平台连接」绑定
4. status=expired → 提示重新登录或检查凭证
5. 向用户复述：平台名 + display_label
```

## 规则

1. **不要编造**未在工具输出中出现的平台或账号
2. 每个智能体 **每个平台最多一个账号**（可同时绑淘宝 + 参谋等多个平台）
3. 绑定在 **平台连接页** 完成，本 skill **只读查询**
4. **不要**使用 `dsagent platforms bindings` shell 命令（阶段 1 后无 JWT 会失败）
5. 用户说「刚绑定好了」时，**必须再次调用工具**，不要沿用对话里更早的空结果

## 示例回复

绑定结果示例：

- 淘宝网: 买家昵称xxx [valid]
- 生意参谋: 登录名xxx [valid]

未绑定时：

> 当前智能体尚未绑定电商账号。请在 DeepSeek Agent 控制台打开 **平台连接**，登录并绑定到本智能体。
