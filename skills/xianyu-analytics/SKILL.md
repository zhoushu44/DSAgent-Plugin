# 闲鱼数据分析

## 何时使用

- 用户说"分析一下我的闲鱼商品数据"、"哪些宝贝卖得好" → 账号概况 + 爆款排行
- 用户说"闲鱼哪些商品没人看"、"帮我找出滞销的" → 疑似滞销清单
- 用户说"看看闲鱼曝光量"、"统计一下闲鱼商品表现" → 全量明细 + 排行
- 用户要经营复盘、选品优化建议 → 先取数据，再基于返回结果给建议

## 边界

- **不做商品采集与比价** —— 搜索他人商品、竞品比价请用 `xianyu-crawl`
- **不做商品发布 / 编辑 / 下架** —— 请用 `xianyu-publish`
- **不做订单与售后** —— 请用 `xianyu-order`
- **不做客服消息** —— 请用 `xianyu-im`
- 只读操作，**不产生任何平台副作用**
- **只统计已发布在售/已下架的自有商品**，不包含买家侧数据
- 数据来自闲鱼个人页展示口径（曝光/想要/收藏），**不是**平台后台的完整漏斗，无成交金额与转化率
- 采集过程会**弹出可见浏览器窗口**；若出现滑块 / 安全验证需用户人工完成
- 同一时间只能有一个闲鱼分析窗口；已有窗口进行中时需等待其结束
- ★ **账号必须是闲鱼 APP 扫码登录**：淘宝 SSO 派生的闲鱼账号在 goofish 域下登录态无效

## 执行流程

本技能**没有脚本入口**，执行方式是**直接调用 host 工具** `dsagent_xianyu_analytics`。

> 为什么不是 Python 脚本：闲鱼账号类接口（`mtop.idle.web.xyh.item.list` 等）要求页面 JS 运行时生成的
> `sign` 签名 + 真实 goofish 域会话票据（`havana_lgc2_77`）。Cookie 注入式纯 HTTP 请求恒返回
> `FAIL_SYS_SESSION_EXPIRED::Session过期`；页面 SSR 内联数据里也没有商品统计。
> 因此由 host 工具用 puppeteer 打开闲鱼个人页、注入账号 Cookie，拦截**页面自身发出**的账号类接口响应取数。

### 1. 收集参数

| 参数 | 必需 | 说明 |
|------|------|------|
| `mode` | 否 | `overview`（账号概况 + 爆款/滞销排行，默认）/ `items`（全量商品明细） |
| `limit` | 否 | 返回条数上限，默认 50，最大 100 |
| `account` | 否 | 指定账号 `shopKey`；多账号待选时回传用户选择 |

### 2. 调用工具

账号概况与排行：

```
dsagent_xianyu_analytics()
```

全量商品明细：

```
dsagent_xianyu_analytics(mode="items", limit="100")
```

### 3. 报告结果

- 成功：把返回结果整理给用户
  - `profile`：账号概况（粉丝 / 关注 / 获赞）
  - `overview` 模式的文本含「账号概况 + 爆款 TOP（按浏览数）+ 疑似滞销（零浏览零想要）」
  - `items` 模式返回结构化 `items` 数组（商品 ID / 标题 / 价格 / 浏览 / 想要 / 收藏 / 城市 / 链接）
  - 基于数据给出可执行建议（如滞销商品改标题、降价、重新擦亮）
- 失败：按返回的 `failureKind` 走下方「错误处理」
- 工具会返回 `sourceUrls`（本次实际命中的接口），排查"没有数据"时把它一并展示

## 错误处理

| 场景 | failureKind | 引导动作 |
|------|-------------|---------|
| 未绑定闲鱼账号 | `not_bound` | 引导用户到「账号连接」页面添加闲鱼账号 |
| 平台有多个可用账号且当前会话未绑定 | `need_account_choice` | **把候选列表给用户选**，把选定的 `shopKey` 填进 `account` 参数重调；★ 绝不要自己挑一个 |
| 账号类接口返回 Session 过期 / 页面仍显示「登录」 | `token_expired` | 引导用户**删除该闲鱼账号后重新添加**，★ 必须用**闲鱼 APP 扫描** `https://www.goofish.com/login` 的二维码；**不要走淘宝 SSO**（SSO 派生的账号在 goofish 域下无效） |
| 接口返回 403 / 429 | `risk_control` | 调用 `dsagent_risk_verify`（platform=xianyu）拉起验证页，用户完成滑块后重试 |
| 拦截到接口但无商品字段 | `parse_error` | 打开浏览器窗口确认是否出现滑块或安全验证，人工完成后重试；若已登录仍无数据，可能是平台接口调整，把 `sourceUrls` 反馈给用户 |
| 账号下没有任何在售商品 | `parse_error` | 说明该账号暂无已发布商品，无需分析 |
| 已有分析窗口在进行中 | `api_error` | 提示先等待或关闭已弹出的浏览器窗口 |
| 未找到 Chrome / Edge | `api_error` | 提示用户安装 Chrome 或 Edge |

## 环境变量

本技能为纯指令型，不执行脚本，无环境变量依赖。
账号凭证由 host 工具从凭证库读取并**在浏览器内注入 Cookie**，日志与返回值均已脱敏，**技能侧不接触 Cookie**。
