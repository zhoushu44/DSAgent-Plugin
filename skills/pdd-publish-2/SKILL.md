# 拼多多 · 商品发布

> **重要:** 发布是**不可撤销的真实操作（L2）**。必须两步走：先拿「发布预览」给用户看，用户**明确同意**后才真正提交。
> 绝不要在一次调用里直接传 `confirm=true`。

## 何时使用

- 用户说「拼多多上架」「拼多多上架2」「拼多多发布」「用统一商品数据发拼多多」「拼多多二维规格上架」→ 用本技能
- 用户给出一件商品的**统一 JSON**（或可组装成该 JSON 的字段：标题 + 图片 + 规格 + SKU 行）要求发到拼多多 → 用本技能
- 商品规格是**二维**（如 颜色 × 尺码）→ 用本技能（支持颜色×尺码矩阵）
- 用户想让**商品属性**按指定值填（而非让模型猜）→ 用本技能（`attributes` 显式指定）

## 能力

| 项 | 说明 |
|---|---|
| 入参 | **只有一个统一 `product`（JSON）** |
| 规格 | **维度数组**（颜色 / 尺码…，≤2 维），SKU 按**维度名→规格值**组合 |
| 二维矩阵 | ✓ 原生支持（颜色×尺码） |
| 属性 | 可**显式指定** name→value（命中页面选项才用），未指定时按页面选项自动选 |
| 执行链路 | 商家后台四段真实链路（浏览器驱动、类目自动搜索、confirm 门禁、账号选择、风控等待） |

## 边界

- **不做商品采集与比价** → 用 `pdd-crawl`
- **不做订单 / 售后** → 用 `pdd-order`；**不做库存管理** → 用 `pdd-stock`；**不做客服消息** → 用 `pdd-im`
- **不做深度数据分析** → 用 `pdd-analytics`
- **不做淘宝 / 天猫发布** → 用 `taobao-publish`；**不做闲鱼发布** → 用 `xianyu-publish`
- **不做批量**：当前只支持**单件**商品发布，多件需逐件调用
- ★ **品牌不会自动填**（涉及品牌授权），需用户在弹出窗口内人工补全
- ★ **商品资质**仍需人工补全（平台因类目而异，无法统一自动化）
- ★ **拼多多商家后台与买家端拼多多是两套完全独立的登录态**：账号连接页需单独绑定「**拼多多商家后台**」

## 输入

工具名 `dsagent_pdd_publish2`。参数只有 3 个：

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `product` | string | 是 | **统一商品数据**，JSON 字符串（结构见下） |
| `confirm` | boolean | 否 | 省略或 `false` → **只返回预览，不产生任何写操作**；`true` → 才真正打开浏览器提交 |
| `account` | string | 否 | 指定账号 `shopKey`；仅在返回 `need_account_choice` 时，把用户选定的 `shopKey` 回传到这里 |

### `product` 统一结构

```jsonc
{
  "title": "秋冬新款儿童宽松睡衣 摇粒绒卡通家居服套装",   // 必填，≤60 字符
  "images": ["D:\\imgs\\1.jpg", "D:\\imgs\\2.jpg"],      // 必填，本地绝对路径，1~10 张，单张 ≤3MB
  "detailImages": ["D:\\imgs\\d1.jpg"],                  // 选填，详情图，最多 50 张，单张 ≤3MB
  "category": "童装 套装",                                // 选填，类目关键词/路径；不传则从标题推断
  "price": "34",                                         // 选填，商品参考价（元）
  "stock": "999",                                        // 选填，默认库存（SKU 行未给库存时回落）；不传默认 1000
  "itemNo": "MUG-350",                                   // 选填，货号/商家编码；不传则不写该列

  // ── 规格维度（选填，最多 2 维；与 skus 配合）──
  "specs": [
    { "name": "颜色", "values": [
        { "value": "奶油黄", "image": "D:\\imgs\\c1.jpg" },   // 第 1 维的值可带预览图（平台按「颜色」上传）
        { "value": "星光粉", "image": "D:\\imgs\\c2.jpg" }
    ] },
    { "name": "尺码", "values": [ { "value": "110cm" }, { "value": "120cm" } ] }
  ],

  // ── SKU 行（选填；每行的 specs 必须覆盖全部维度）──
  "skus": [
    { "specs": { "颜色": "奶油黄", "尺码": "110cm" }, "price": "34", "stock": "999" },
    { "specs": { "颜色": "奶油黄", "尺码": "120cm" }, "price": "36", "stock": "999" }
  ],

  // ── 商品属性（选填，显式 name→value；命中页面下拉选项才生效）──
  "attributes": [ { "name": "主面料成分", "value": "棉" }, { "name": "安全等级", "value": "A类" } ],

  // ── 发货与售后（选填，自动填；不传则默认非预售+当日发货）──
  "costTemplate": "默认运费模板",                             // 选填，运费模板名；传入后自动选「其他模板」→搜索该名称
  "deliveryTime": 1,                                         // 选填，1=当日发货(默认)、2=24小时发货、3=48小时发货

  "account": "pdd_mms_xxxx"                              // 选填，指定账号 shopKey
}
```

**字段规则**

- `title` **必填**、≤60 字符；`images` **必填**、1~10 张、单张 ≤3MB（本机绝对路径且真实存在）
- `specs` ≤2 维；每维名非空且不重复；每维值 1~20 个、不重复；**仅第 1 维的值可带 `image`**（平台按「颜色」上传预览图：宽高比 1:1、宽高均 >480px、单张 <3MB、仅 JPG/PNG）
- `skus` 每行 `specs` 必须**覆盖全部维度**；`price` 为正数、`stock` 为非负整数（缺项回落顶层 `price`/`stock`）
- 兼容富格式：若没有 `specs`，但有 `colors[]` + `sizes[]`（如 `pdd-link-matrix` 产出的商品 JSON），会自动合成「颜色」「尺码」两维；`skus` 也兼容用维度名做扁平键、以及 `折后价(元)` / `可订库存` 等列名
- `attributes` 里 `品牌` 一律**不自动填**（涉及品牌授权，留给人工）

**默认值约定** —— 用户没提到的字段直接照下面来，**不要为这些去追问用户**：

- **库存**：`stock` 省略时工具默认填 **1000**（SKU 行未给库存也回落到它）
- **单买价**：工具自动按 **拼单价 + 1 元** 算，无需传参
- **货号 / 商家编码**：**不写** —— 不传 `itemNo`

## 输出

返回一个 JSON 对象，字段与旧版一致：

| 字段 | 类型 | 含义 |
|------|------|------|
| `ok` | boolean | 业务是否成功。★ **取预览时是 `ok=false` + `needConfirm=true`，这是正常流程，不是报错** |
| `needConfirm` | boolean? | 为 `true` 表示「这是预览，等用户确认」 |
| `text` | string | 面向用户的中文文案 —— **预览内容、成功详情、失败原因全都在这个字段里**，原样转述给用户即可 |
| `failureKind` | string? | 失败分类：`not_bound` / `need_account_choice` / `token_expired` / `risk_control` / `api_error` |
| `accounts` | array? | 仅 `need_account_choice` 时出现。候选账号（不含 Cookie） |
| `shopKey` | string? | 实际使用的账号标识 |
| `finalUrl` | string? | 当时的页面 URL |

预览里会逐维列出规格值与 SKU 组合（形如 `SKU 组合（N 行）` + 每行 `颜色=奶油黄 / 尺码=110cm：拼单价 34 / 单买价 35 / 库存 999`），以及显式指定的商品属性。

三种典型返回：

**① 预览**（`confirm` 未传）

```json
{
  "ok": false,
  "needConfirm": true,
  "text": "【发布预览 · 需用户确认】\n渠道：拼多多（商家后台 mms.pinduoduo.com）\n账号：张三（pdd_mms_xxxx）\n标题：秋冬新款儿童宽松睡衣 摇粒绒卡通家居服套装\n类目：平台按发布入口自动搜索推荐\n商品参考价：34\n库存：999\n货号：（未填）\n主图（2 张）：\n  - D:\\imgs\\1.jpg\n  - D:\\imgs\\2.jpg\n规格维度（2 维）：\n  - 颜色（2 个值）：奶油黄、星光粉\n  - 尺码（2 个值）：110cm、120cm\nSKU 组合（4 行）：\n  - 颜色=奶油黄 / 尺码=110cm：拼单价 34 / 单买价 35 / 库存 999\n  ...\n商品属性（显式指定）：\n  - 主面料成分=棉\n\n★ 本工具自动填「类目 / 主图 / 标题 / 商品参考价 / 库存 / 货号 / 商品详情图 / SKU 规格（含预览图与价格）/ 商品属性（品牌除外）/ 发货与售后（非预售+当日发货）/ 运费模板（如指定）」，
  品牌和商品资质需在弹出的浏览器窗口内人工补全后提交。\n\n确认无误后，请让用户明确同意，然后带 confirm=true 重新调用本工具才会真正打开浏览器提交。\n注意：发布是不可撤销的真实操作（L2）。"
}
```

**② 成功**

```json
{
  "ok": true,
  "shopKey": "pdd_mms_xxxx",
  "finalUrl": "https://mms.pinduoduo.com/goods/goods_add/success?goods_id=1008817921511",
  "text": "拼多多商品发布已提交成功。\n账号：张三（pdd_mms_xxxx）\n标题：…\n商品ID：1008817921511\n已自动填写：类目（平台自动推荐）、标题=…、参考价=34、库存=999、拼单价=34、单买价=35\n当前页面：…\n注意：平台仍会对商品做审核，最终状态请在商家后台「商品管理 → 出售中」确认。"
```

## 执行流程

本技能**没有脚本入口**，执行方式是**直接调用 host 工具** `dsagent_pdd_publish2`。

> 为什么不是 Python 脚本：拼多多商家后台发布页的类目、属性与提交接口都要求页面 JS 运行时生成的签名与真实会话票据，
> 且主图走 multipart 二进制上传（本地代理网关不支持 multipart），因此由 host 工具用 puppeteer 驱动商家后台完成填写与提交。

### 1. 组装 `product`

从用户话里提取字段组装统一 JSON；`title` 与 `images` 是必需项，缺了就主动问。
若用户给的是**富格式商品数据**（含 `colors[]` / `sizes[]` / `skus` 扁平键），可**原样传入**，解析器会自动归一化。

### 2. 先取「发布预览」（不带 confirm）

调用 `dsagent_pdd_publish2`，**只传 `product`，不要传 `confirm`**：

```
dsagent_pdd_publish2(product='{"title":"秋冬新款儿童宽松睡衣 摇粒绒家居服套装","images":["D:\\imgs\\1.jpg","D:\\imgs\\2.jpg"],"price":"34","stock":"999","specs":[{"name":"颜色","values":[{"value":"奶油黄","image":"D:\\imgs\\c1.jpg"}]},{"name":"尺码","values":[{"value":"110cm"}]}],"skus":[{"specs":{"颜色":"奶油黄","尺码":"110cm"},"price":"34","stock":"999"}]}')
```

工具此时**不会启动浏览器、不产生任何写操作**，只返回预览：`ok=false` + `needConfirm=true`。
★ 这个 `ok=false` 是**正常流程**，不是报错。

### 3. 把预览完整展示给用户并征求明确同意

把 `text` 原样呈现给用户，并明确问一句类似"确认要发布吗？"。
同时**必须提醒用户**：品牌和商品资质不会被自动填写，稍后需要在弹出的浏览器窗口内人工补全。

**这一步不可跳过、不可自行假设用户同意**（L2 风险门禁）。

### 4. 用户同意后带 `confirm=true` 重新调用

```
dsagent_pdd_publish2(product='{…同上…}', confirm=true)
```

工具会弹出可见浏览器窗口，依次完成：
注入登录态 → 打开商品列表 → 点「发布新商品」→ **类目选择页**（按 `category`/标题关键词搜索并选类目 →「确认发布该类商品」）→
**表单页**（主图 / 标题 / 参考价 / 库存 / 货号 / 详情图 / **规格维度与 SKU 行**（逐维建规格、逐行填价格与预览图）/ 尝试自动填商品属性）→ 点「提交并上架」→ 判定结果。

> 两个**已知的稳定现象**，看到时不要当成故障：
> · 首次点「下一步」可能被页面时序吞掉，工具会**自动补点一次**（整体耗时因此偏长，属正常）；
> · 提交被平台拦下时页面**不弹 toast**，拦因只出现在右侧「商品填写建议」面板，工具会读该面板并把真实原因写进返回值。

### 5. 报告结果

- `ok=true`：告知已提交发布、商品 ID，并说明**平台仍会审核**，最终状态以商家后台「商品管理 → 出售中」为准；同时转告 `text` 里的**未自动填写字段**清单
- `ok=false` 且 `needConfirm=true`：这是预览，回到第 3 步征求用户同意
- `ok=false` 且带 `failureKind`：按下方「错误处理」走

## 平台硬规则（工具已内化，回答用户时可引用）

| 规则 | 说明 |
|------|------|
| 拼单价必须大于 0 | 拼单价留空或为 0 会被拦「拼单价必须大于0」 |
| 单买价必须 ≥ 拼单价 + 1 元 | 两列同值必被拦；工具自动按 **拼单价 + 1** 填单买价 |
| 库存必填 | 库存留空会被拦「请输入库存」；`stock` 省略时**默认填 1000** |
| 货号默认为空 | `itemNo` 不传就不写「规格编码 / 商品编码」列 |
| SKU 预览图是提交必填项 | 第 1 维（颜色）每个值的 `image` 都要提供，且需「宽高比 1:1、宽高均 >480px、单张 <3MB、仅 JPG/PNG」 |
| 规格最多 2 个维度 | 每维规格值最多 20 个 |
| 参考价与拼单价的关系 | 参考价（划线价）应为展示价，一般 ≥ 拼单价 |

## 错误处理

| 场景 | failureKind | 引导动作 |
|------|-------------|---------|
| 未绑定拼多多商家后台账号 | `not_bound` | 引导用户到「账号连接」页面添加**拼多多商家后台**账号（登录 mms.pinduoduo.com）；★ 买家端拼多多账号不能用于发布 |
| 平台有多个可用账号且当前会话未绑定 | `need_account_choice` | **把候选列表给用户选**，把选定的 `shopKey` 填进 `account` 参数重调；★ 绝不要自己挑一个 |
| 商家后台登录态失效 | `token_expired` | 引导用户到「账号连接」页面**重新登录拼多多商家后台** |
| 提交时命中「请向右滑块完成拼图」 | `risk_control` | 工具会等 120s 让用户在窗口内完成拼图并自动继续提交；若超时，让用户重试本工具并**在窗口内拖动滑块** |
| `product` 不是合法 JSON / 缺少 title 或 images / 标题超 60 字符 / 价格或库存越界 | `api_error` | 按返回文案修正 `product` 后重试（校验在浏览器启动**之前**完成，不会产生写操作） |
| 规格维度 >2 / 维度名重复 / 规格值重复或超 20 / SKU 行未覆盖全部维度 / 规格值预览图不存在或超 3MB | `api_error` | 按返回文案修正 `product` 后重试 |
| 未找到商品列表页的「发布新商品」入口 | `api_error` | 让用户打开浏览器窗口**手动点「发布新商品」**，或稍后重试（页面结构可能已变更） |
| 点击后 60s 内未出现类目选择页 | `api_error` | 让用户确认新标签页是否被浏览器拦截弹窗，允许弹窗后重试 |
| 提交后提示资质 / SKU 预览图未填 | `api_error` | 资质**不由本工具自动填写**，让用户在窗口内补全后手动点「提交并上架」；若提示的是 **SKU 预览图**，多为图片不满足尺寸规则，让用户换图或人工上传 |
| 提交后 180s 内未检测到成功标志 | `api_error` | 让用户查看窗口内提示：补全红色校验项后手动提交；若有滑块需人工完成；成功可在「商品管理 → 出售中」核对 |
| 商品属性自动填失败（属性区未定位 / 模型不可用） | —— | **不阻断发布**，只是该属性留空；非必填属性留空不影响提交 |
| 已有拼多多商家后台浏览器任务在进行中 | `api_error` | 提示先等待该任务结束或关闭已弹出的浏览器窗口 |
| 未找到 Chrome / Edge | `api_error` | 提示用户安装 Chrome 或 Edge |

## 商品属性自动填

**显式指定优先**：`product.attributes` 里给了 `name→value` 时，工具优先用该值——命中页面下拉选项才点选；
**未命中就记入「未填」并不走模型**（显式值不会被模型改写）。

未显式指定的属性，由 host 工具调用**当前会话正在使用的 DSH 对话模型**（`ctx.llm.stream`）从「页面真实下拉选项」里挑一个值，
**无需任何额外配置**。模型不可用（会话无模型路由）时，自动走**标题词匹配兜底**（从标题提取关键词匹配选项），匹配不到则**选第一个选项**（对齐神笔 step 10）。
`品牌` 一律不自动填。

账号凭证由 host 工具从凭证库读取并**在浏览器内注入 Cookie**，日志与返回值均已脱敏，**技能侧不接触 Cookie**。
