# Image Diagnose · 眼动证据驱动的图片诊断

## Overview

对**已存在的图片**做主图/SKU图/详情页的独立评估。核心不是"好看不好看"，
而是**用户在真实浏览条件下，眼睛会落在哪、能不能在 3 秒内完成购买决策所需的
信息提取**。

与 `image-gen`（出图）、`image-prompt-guide`（提示词）的关系：
本技能产出「该改什么」→ 交给 image-prompt-guide 写提示词 → image-gen 执行重出。
**本技能不生成图片。**

## 判断依据的三个层级

| 层级 | 依据 | 可信度 | 本技能如何用 |
|---|---|---|---|
| L1 眼动实验证据 | 已发表的眼动研究结论（见 `references/eye-tracking-evidence.md`） | 高，有统计支撑 | **判断的主干**。热区位置、首扫路径、注视时长阈值都从这里出 |
| L2 平台数据 | CTR / 停留 / 转化（拼多多 `pdd-promo` 创意报表、A/B 测试） | 高，但是事后 | 作为**验证层**：诊断预测 vs 实际数据，校准下次判断 |
| L3 画面硬指标 | 尺寸/体积/白底纯度/文字清晰度/形变 | 确定，零成本 | 作为**否决项**：不达标直接打回，不进入审美讨论 |

**铁律：L1 是主，L2 是校准，L3 是准入门槛。不允许用 L3 的合规通过冒充 L1 的诊断通过。**

## 工作流

### Step 1 — 输入盘点

读图前先确认：

1. **图片类型**：主图（3:4 / 1:1 / 白底）/ SKU 上身图 / 详情页单屏 / 详情页长图
2. **品类**：决定用哪套眼动基准（服装 vs 家居 vs 标品差异极大）
3. **平台**：决定合规边界（拼多多数值规格未覆盖，用实测值；淘宝/抖音有明确禁项）
4. **使用位置**：搜索结果页首图 / 轮播第 N 张 / 详情页第几屏
   —— **同一张图在不同位置的评价标准不同**，必须在诊断里写清位置

> 用户未说明位置时，按「搜索结果首图」评估，并在报告里声明这个假设。

### Step 2 — 采样图识别（先于一切判定）

**最容易犯的错：拿搜索页缩略图当原图诊断。**

搜索页抓下来的图常带平台渲染标记（`_580x580q90.jpg_.webp`、
`_400x400`、`_360x360` 等），这是平台为列表页加载速度生成的采样图，
**原图已被压缩，与商家实际上传质量无关**。

`check_metrics.py` 已内置识别，命中即标 `is_thumbnail`。
采样图上**尺寸/锐度/体积阈值全部失效**，但**构图、场景、文案形式仍可判**。

规则：
- 判构图/文案 → 可以，直接进 L1
- 判尺寸/清晰度 → 停下，报告写「需抓原图」，不许给质量结论

详见 `references/platform-thresholds.md` 第零节。

### Step 3 — L3 硬指标否决（先跑，不达标直接停）

用 `scripts/check_metrics.py` 扫。**先按图片类型选档位**
（场景图 `--type scene` 不查白底占比）：

| 档位 | 用于 | 长边 | 体积 | 白底占比 |
|---|---|---|---|---|
| `main` | 白底/纯背景主图 | ≥750 | ≤3MB | ≥85% |
| `scene` | 场景图、模特图 | ≥750 | ≤3MB | 不查 |
| `sku` | SKU 颜色图 | ≥600 | ≤2MB | 不查 |
| `pdp` | 详情页单屏 | ≥750 | ≤3MB | 不查 |

| 指标 | 主图阈值 | SKU图阈值 | 详情页阈值 |
|---|---|---|---|
| 长边像素 | ≥750 | ≥600 | ≥750 |
| 文件体积 | ≤3MB | ≤2MB | ≤3MB |
| 白底占比（首图） | ≥85% 或纯白 | 不限 | 不限 |
| 文字对比度 | ≥4.5:1 | ≥4.5:1 | ≥4.5:1 |
| 商品形变 | 无 | 无 | 无 |

**L3 任一项不过 → 报告直接给「不可用 + 原因 + 修复指令」，不进入 L1。**
理由：形变和超限是平台驳回和降权的确定原因，先于任何审美判断。

### Step 4 — L1 眼动证据诊断（核心）

读 `references/eye-tracking-evidence.md`，按「眼动 → 决策」映射逐项判：

**A. 首扫热区（First 3 Seconds）**

用户扫搜索结果页时，眼睛不是均匀扫，是按固定模式跳。诊断图是否把
**关键信息放进了热区**：

- 主图首扫热区 = 画面中央偏上 + 商品主体占据区
- 若关键卖点（品类词、给谁用）落在热区外 → 判「首扫失效」
- 若商品主体占比 <50% → 判「主体不突出」，搜索缩略图下直接认不出是什么

**B. 注视停留任务（What Holds the Gaze）**

眼动实验里，停留超过 1 秒的区域才会被处理进工作记忆。判断：

- 图上有没有一个「值得盯」的点？没有 → 平庸图，扫过即走
- 文字块的注视顺序是否与阅读顺序一致？中文是从左到右、上到下
- 多个文字块是否互相抢注意？**超过 3 个平级文字块 = 注意力稀释**

**C. 决策信息完整性（3 秒法则）**

首图要在 3 秒内回答三个问题，缺一个就是断点：

1. **这是什么**（品类识别）
2. **给谁用**（人群/场景识别，童装尤其关键）
3. **凭什么信**（一个信任锚点：细节、材质、真人/实拍感）

> 这不是审美，是眼动实验里「任务完成时间」的分解。三个问题任一答不上，
> 用户就要点进去看详情页——**点击前的犹豫直接压 CTR**。

**D. 详情页逐屏（滚动衰减）**

详情页不是平均用力，是按屏衰减：

- 第 1 屏：定调，必须回答「这是什么 + 给谁穿」
- 第 2-3 屏：信任建立（面料、细节、工艺）
- 第 4-5 屏：场景证明（穿出去什么样）
- 第 6 屏后：尺码/规格/售后

判断每屏是否完成了它的**单一任务**。一屏塞两个以上任务 = 该屏失效。
**第 1 屏没做对，后面全部白做**——因为用户已经划走了。

**E. SKU 图（颜色 + 尺码双决策）**

SKU 图要同时支撑两个决策：选色、选码。

- 颜色是否可辨？（同色系 SKU 必须能一眼区分，不能靠猜）
- 尺码是否有可参照物？（纯平铺无参照 → 用户无法判断大小）
- SKU 图与主图是否同一光线/色温？（色差会让用户以为收到不一样的货）

### Step 5 — 输出诊断报告

固定结构，见 `references/report-template.md`。必须包含：

1. **总评**：可用 / 需改 / 不可用（三档，不许说"还行"）
2. **L3 硬指标表**：实测值 vs 阈值
3. **L1 诊断**：逐项给出「通过 / 缺陷 / 失效」，每条缺陷必须指向
   `references/eye-tracking-evidence.md` 里的具体证据编号
4. **修复指令**：具体到"改哪里、改成什么"，可直接转给 image-prompt-guide
5. **重出优先级**：多张图时按 CTR 影响力排序（首图 > 第2张 > SKU图 > 详情页）

### Step 6 — L2 数据校准（有数据时）

若该链接已有推广数据，用 `pdd-promo` 拉创意报表，做一次**预测 vs 实际**对照：

- 诊断判「首扫失效」→ CTR 是否显著低于同类目中位？
- 诊断判「可用」→ CTR 是否达标？

**校准结论写回 `references/calibration-log.md`**，作为下次判断的先验。
没有数据时跳过本步，但报告里要标明「未经数据校准」。

## 禁止事项

1. **不许无证据地说"不好看""不够高级"**。每条批评必须落到眼动证据编号
   或 L3 硬指标。审美偏好不是诊断。
2. **不许编造平台规格**。拼多多数值规格技能库标注 not covered，
   用实测值并注明来源。
3. **不许跳过 L3 直接谈 L1**。形变超限的图没有诊断价值，只有修复价值。
4. **不许把采样图当原图判质量**。见 Step 2。这是本技能最容易犯的错，
   已真实踩过：40 张同行主图全部报"长边 580 不达标"，
   实际是淘宝 `_580x580q90` 采样图，原图质量未知。
5. **不许用白底图标准卡场景图**。场景图查白底占比 = 误判。
6. **不许把多张图的问题合并成一句话**。逐张、逐维度、逐证据。
7. **不许给出"建议优化"这类空话**。修复指令必须能被 image-prompt-guide
   直接当成需求执行。
