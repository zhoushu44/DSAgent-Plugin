# 拼多多 · 商品发布

> **重要:** 发布是**不可撤销的真实操作（L2）**。必须两步走：先拿「发布预览」给用户看，用户**明确同意**后才真正提交。
> 绝不要在一次调用里直接传 `confirm=true`。

## 何时使用

- 用户说"帮我把这个发到拼多多"、"拼多多上架"、"拼多多发布商品"、"上传商品到拼多多" → 发布商品到拼多多商家后台
- 用户给出本地图片路径 + 标题（可选类目/详情图/SKU 图与价格/库存/货号），要求发布到拼多多 → 发布商品
- 用户说"把这批货铺到拼多多" → 单件发布（本技能**不做批量**，需逐件调用）

## 边界

- **不做商品采集与比价** → 用 `pdd-crawl`
- **不做订单 / 售后** → 用 `pdd-order`
- **不做库存管理** → 用 `pdd-stock`
- **不做客服消息** → 用 `pdd-im`
- **不做深度数据分析** → 用 `pdd-analytics`
- **不做淘宝 / 天猫发布** → 用 `taobao-publish`；**不做闲鱼发布** → 用 `xianyu-publish`
- **不生成文案** → 标题与价格由用户提供（可先用通用文案技能生成，再回到本技能发布）
- **不做批量发布、定时发布、批量上下架** —— 当前只支持**单件**商品发布
- ★ **类目不由本工具选择**：拼多多类目由平台按发布入口的智能推荐自动带出；需要改类目请在第二步页面点「修改分类」
- ★ **只自动填通用字段 + 详情页图片 + SKU 多规格**，并尝试自动填**部分商品属性**（材质种类 / 容量 / 适用场景 之类由平台按类目动态给出的下拉项）。
  **发货与售后设置、运费模板、商品资质、品牌不会自动填**，需要在弹出的浏览器窗口内由用户人工补全
- ★ **用户给过来的通常是「类目 + 标题 + 主图 + 详情页 + SKU 图+价格」**：类目由平台自动推荐（不用传或仅作提示），
  其余四项分别对应 `images` / `detailImages` / `skus`；**单买价与库存没提就按默认值**（单买价 = 拼单价 + 1，库存 1000）
- ★ **属性自动填充依赖一个文本模型**：模型不可用时会直接跳过（不阻断发布），日志会记录「未命中」
- 图片必须是**本机绝对路径**且真实存在，**1~10 张**（拼多多主轮播图上限），单张 **≤ 3MB**（超出请先压缩）
- 标题**必填**且**不超过 60 个字符**（拼多多 placeholder 标注「最多输入30个汉字（60个字符）」）
- 参考价（可选）为正数、1 亿元以内；库存（可选）为非负整数，**不传时工具默认填 1000**；货号（可选）**默认不写**
- 发布过程会**弹出可见浏览器窗口**（真实操作，用户可见）；若出现滑块拼图需人工完成
- 同一时间只能有一个拼多多商家后台浏览器任务；已有任务进行中时需等待其结束
- ★ **拼多多商家后台与买家端拼多多是两套完全独立的登录态**：账号连接页需单独绑定「**拼多多商家后台**」账号，
  买家端账号（`pdd-crawl` 用的那套）**不能**用于发布商品

## 输入

工具名 `dsagent_pdd_publish`。除 `confirm` 是布尔，**其余参数都是字符串**。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `title` | string | 是 | 商品标题。**不超过 60 个字符** |
| `images` | string | 是 | 本地图片文件**绝对路径**，1~10 张，单张 ≤ 3MB。多张用**英文逗号分隔**，或传 **JSON 数组字符串** |
| `detailImages` | string | 否 | **商品详情页图片**本地绝对路径，最多 **50 张**、单张 ≤ 3MB。写法同 `images`（逗号分隔或 JSON 数组字符串）。用户没给详情图就省略 |
| `skus` | string | 否 | **SKU 多规格**，JSON 数组字符串，形如 `[{"name":"白色","image":"C:/img/w.jpg","price":"9.9","stock":"1000"}]`。`name` 规格值名（必填）、`image` 该规格**预览图**本地路径（**平台必填**：宽高比 1:1、宽高均 >480px、单张 <3MB、仅 JPG/PNG）、`price` 拼单价（元）、`stock` 库存。★ **单买价自动 = 拼单价 + 1**，不用传。用户没给 SKU 就省略 |
| `category` | string | 否 | 类目关键词或完整路径（如「纸杯」）。★ 仅作提示，**不会自动选类目** |
| `price` | string | 否 | 商品参考价（元，字符串数字）。正数、1 亿元以内；填了会按「拼单价 + 1 元」自动算单买价 |
| `stock` | string | 否 | 库存（件，字符串数字）。非负整数、1 亿以内。★ **没要求就不传，工具默认按 1000 填** |
| `itemNo` | string | 否 | 商家编码 / 货号。★ **默认不写**（用户没提货号就不要传） |
| `confirm` | boolean | 否 | 省略或 `false` → **只返回预览，不产生任何写操作**；`true` → 才真正打开浏览器提交 |
| `account` | string | 否 | 指定账号 `shopKey`；仅在返回 `need_account_choice` 时，把用户选定的 `shopKey` 回传到这里 |

`images` 两种写法等价：

```
dsagent_pdd_publish(images="D:\imgs\1.jpg,D:\imgs\2.jpg", title="简约陶瓷马克杯 350ml 办公家用咖啡杯", price="19.9")
dsagent_pdd_publish(images='["D:\\imgs\\1.jpg","D:\\imgs\\2.jpg"]', title="简约陶瓷马克杯 350ml 办公家用咖啡杯", price="19.9")
```

带详情图与 SKU 多规格的完整写法：

```
dsagent_pdd_publish(
  title="简约陶瓷马克杯 350ml 办公家用咖啡杯",
  images="D:\imgs\1.jpg,D:\imgs\2.jpg",
  detailImages="D:\imgs\d1.jpg,D:\imgs\d2.jpg",
  skus='[{"name":"白色","image":"D:\\imgs\\sku-white.jpg","price":"19.9","stock":"1000"},{"name":"黑色","image":"D:\\imgs\\sku-black.jpg","price":"21.9"}]'
)
```

**默认值约定** —— 用户没提到的字段直接照下面来，**不要为这些去追问用户**：

- **库存**：省略 `stock`，工具按 **1000** 填（预览里会显示「库存：1000」，用户可在确认前叫停）
- **单买价**：工具自动按 **拼单价 + 1 元** 算，无需传参（顶层参考价与每个 SKU 的拼单价都如此）
- **货号 / 商家编码**：**不写** —— 不传 `itemNo`

## 输出

返回一个 JSON 对象，字段是固定的：

| 字段 | 类型 | 含义 |
|------|------|------|
| `ok` | boolean | 业务是否成功。★ **取预览时是 `ok=false` + `needConfirm=true`，这是正常流程，不是报错** |
| `needConfirm` | boolean? | 为 `true` 表示「这是预览，等用户确认」 |
| `text` | string | 面向用户的中文文案 —— **预览内容、成功详情、失败原因全都在这个字段里**，原样转述给用户即可 |
| `failureKind` | string? | 失败分类：`not_bound` / `need_account_choice` / `token_expired` / `risk_control` / `api_error`（含义见「错误处理」） |
| `accounts` | array? | 仅 `need_account_choice` 时出现。候选账号，每项含 `nickname` / `accountId` / `shopKey` / `status`，**不含 Cookie** |
| `shopKey` | string? | 实际使用的账号标识；失败时也会带上，便于排查 |
| `finalUrl` | string? | 当时的页面 URL |

三种典型返回：

**① 预览**（`confirm` 未传）—— 真实措辞即下面这段，直接把 `text` 展示给用户

```json
{
  "ok": false,
  "needConfirm": true,
  "text": "【发布预览 · 需用户确认】\n渠道：拼多多（商家后台 mms.pinduoduo.com）\n账号：张三（pdd_mms_xxxx）\n标题：简约陶瓷马克杯 350ml 办公家用咖啡杯\n类目：平台按发布入口自动推荐\n商品参考价：19.9\n库存：1000\n货号：（未填）\n主图（2 张）：\n  - D:\\imgs\\1.jpg\n  - D:\\imgs\\2.jpg\n详情图（2 张）：\n  - D:\\imgs\\d1.jpg\n  - D:\\imgs\\d2.jpg\nSKU 多规格（2 个规格值）：\n  - 白色：拼单价 19.9 / 单买价 20.9 / 库存 1000 / 预览图 D:\\imgs\\sku-white.jpg\n  - 黑色：拼单价 21.9 / 单买价 22.9 / 库存 1000 / 预览图 D:\\imgs\\sku-black.jpg\n\n★ 本工具自动填「类目 / 主图 / 标题 / 商品参考价 / 库存 / 货号 / 商品详情图 / SKU 规格（含预览图与价格）」，\n  并尽力自动选「商品属性」（品牌除外）。\n  发货与售后设置、运费模板、商品资质等**不会**被自动填写，\n  需要在弹出的浏览器窗口内人工补全后提交（这与拼多多后台的必填项策略一致）。\n\n确认无误后，请让用户明确同意，然后带 confirm=true 重新调用本工具才会真正打开浏览器提交。\n注意：发布是不可撤销的真实操作（L2）。"

```

**② 成功** —— `已自动填写` 一行按实际命中的字段拼接，未命中任何字段时整行不出现

```json
{
  "ok": true,
  "shopKey": "pdd_mms_xxxx",
  "finalUrl": "https://mms.pinduoduo.com/goods/goods_add/success?goods_id=1008817921511",
  "text": "拼多多商品发布已提交成功。\n账号：张三（pdd_mms_xxxx）\n标题：简约陶瓷马克杯 350ml 办公家用咖啡杯\n商品ID：1008817921511\n已自动填写：类目（平台自动推荐）、标题=简约陶瓷马克杯 350ml 办公家用咖啡杯、参考价=19.9、库存=1000、拼单价=19.9、单买价=20.9、规格/商品编码=MUG-350、材质=陶瓷\n当前页面：https://mms.pinduoduo.com/goods/goods_add/success?goods_id=1008817921511\n注意：平台仍会对商品做审核，最终状态请在商家后台「商品管理 → 出售中」确认。"

```

> `已自动填写` / `未自动填写（需人工确认）` 两行的条目形态是固定的（与代码里 push 的标签一致）：
> `类目（平台自动推荐）`、`标题=<标题>`、`参考价=<值>`、`库存=<值>`、`拼单价=<值>`、`单买价=<值>`、

> 说明这些字段**页面上确实没填上**，要提醒用户在「商品管理」里核对。

## 执行流程

本技能**没有脚本入口**，执行方式是**直接调用 host 工具** `dsagent_pdd_publish`。

> 为什么不是 Python 脚本：拼多多商家后台的发布链路需要**真实两步式页面上下文**——
> 第一步页（`/goods/category`）与第二步表单（`/goods/goods_add/index`）的
> `type=add&from=category&version=predictCate&id=<类目id>&goods_id=<商品id>` 参数由平台在点
> 「发布新商品」时即时生成，直接敲表单 URL 只会得到空壳页；且主图走 multipart 二进制上传，
> 本地代理网关不支持 multipart。因此由 host 工具用 puppeteer 驱动商家后台完成填写与提交。

### 1. 收集参数

按上文「输入」的清单从用户话里提取参数；`title` 与 `images` 是必需项，缺了就主动问。

### 2. 先取「发布预览」（不带 confirm）

调用 `dsagent_pdd_publish`，**只传业务参数，不要传 `confirm`**：

```
dsagent_pdd_publish(images="D:\imgs\1.jpg,D:\imgs\2.jpg", title="简约陶瓷马克杯 350ml 办公家用咖啡杯", price="19.9")
```

工具此时**不会启动浏览器、不产生任何写操作**，只返回预览：
`ok=false` + `needConfirm=true`，预览文本全在 `text` 字段里（含账号、标题、类目、参考价、库存、货号、主图、详情图、SKU 多规格）。
★ 这个 `ok=false` 是**正常流程**，不是报错。

### 3. 把预览完整展示给用户并征求明确同意

把 `text` 原样呈现给用户，并明确问一句类似"确认要发布吗？"。
同时**必须提醒用户**：发货与售后设置、运费模板、商品资质不会被自动填写，稍后需要在弹出的浏览器窗口内人工补全。

**这一步不可跳过、不可自行假设用户同意**（L2 风险门禁）。

### 4. 用户同意后带 `confirm=true` 重新调用

```
dsagent_pdd_publish(images="D:\imgs\1.jpg,D:\imgs\2.jpg", title="简约陶瓷马克杯 350ml 办公家用咖啡杯", price="19.9", confirm=true)
```

工具会弹出可见浏览器窗口，依次完成：
注入登录态 → 打开商品列表 → 点工具栏「发布新商品」→ **第一步**（上传主图 + 填标题）→ 点「下一步, 完善商品信息」→
**第二步**表单（参考价 / 库存 / 商家编码 + **商品详情图** + **SKU 多规格**（规格类型→规格值→每行预览图）+ 逐行拼单价/单买价/库存 + 尝试自动填商品属性）
→ 点「提交并上架」→ 判定结果。

> 两个**已知的稳定现象**，看到时不要当成故障：
> · 首次点「下一步」可能被页面时序吞掉，工具会**自动补点一次**（整体耗时因此偏长，属正常）；
> · 提交被平台拦下时页面**不弹 toast**，拦因只出现在右侧「商品填写建议」面板，工具会读该面板并把真实原因写进返回值。

### 5. 报告结果

按上面「输出」的字段解读返回值，`text` 就是给用户看的文案：

- `ok=true`：告知已提交发布、商品 ID（在 `text` 里，若页面返回），并说明**平台仍会审核**，最终状态以商家后台「商品管理 → 出售中」为准；
  同时把 `text` 里的**未自动填写字段**清单明确转告用户，提醒核对
- `ok=false` 且 `needConfirm=true`：这是预览，回到第 3 步征求用户同意
- `ok=false` 且带 `failureKind`：按返回的 `failureKind` 走下方「错误处理」

## 平台硬规则（工具已内化，回答用户时可引用）

| 规则 | 说明 |
|------|------|
| 拼单价必须大于 0 | 拼单价留空或为 0 会被拦「拼单价必须大于0」 |
| 单买价必须 ≥ 拼单价 + 1 元 | 两列同值必被拦「单买价至少比拼单价高1元」；工具自动按 **拼单价 + 1** 填单买价 |
| 库存必填 | 库存留空会被拦「请输入库存」；本工具在 `stock` 省略时**默认填 1000** |
| 货号默认为空 | `itemNo` 不传就不写「规格编码 / 商品编码」列（该列平台非必填） |
| SKU 预览图是提交必填项 | 每个规格的 `image` 都要提供，且需「宽高比 1:1、宽高均 >480px、单张 <3MB、仅 JPG/PNG」，否则会被平台拦下 |
| 规格最多 2 个规格类型 | 本工具固定用规格类型「颜色」，规格值名支持中英文、数字、空格与部分英文符号（≤40 字）；规格值最多 20 个 |
| 参考价与拼单价的关系 | 参考价（划线价）应为展示价，一般 ≥ 拼单价 |

## 错误处理

| 场景 | failureKind | 引导动作 |
|------|-------------|---------|
| 未绑定拼多多商家后台账号 | `not_bound` | 引导用户到「账号连接」页面添加**拼多多商家后台**账号（登录 mms.pinduoduo.com，可用拼多多 App 扫码或账号密码）；★ 买家端拼多多账号不能用于发布 |
| 平台有多个可用账号且当前会话未绑定 | `need_account_choice` | **把候选列表给用户选**，把选定的 `shopKey` 填进 `account` 参数重调；★ 绝不要自己挑一个 |
| 商家后台登录态失效（页面要求登录） | `token_expired` | 引导用户到「账号连接」页面**重新登录拼多多商家后台** |
| 提交时命中「请向右滑块完成拼图」 | `risk_control` | 工具会等 120s 让用户在窗口内完成拼图并自动继续提交；若超时，让用户重试本工具并**在窗口内拖动滑块** |
| 图片不存在 / 超过 3MB / 超过 10 张 | `api_error` | 按提示修正图片路径或压缩后重试 |
| 标题为空 / 超过 60 字符 / 参考价或库存越界 | `api_error` | 按提示修正参数后重试 |
| 未找到商品列表页的「发布新商品」入口 | `api_error` | 让用户打开浏览器窗口**手动点「发布新商品」**，或稍后重试（页面结构可能已变更） |
| 点击后 60s 内未出现第一步页面 | `api_error` | 让用户确认新标签页是否被浏览器拦截弹窗，允许弹窗后重试 |
| 提交后提示发货与售后 / 运费模板 / 资质 / SKU 预览图未填 | `api_error` | ★ 前几项**不由本工具自动填写**，让用户在窗口内补全后手动点「提交并上架」；若提示的是 **SKU 预览图**，多为图片不满足「宽高比 1:1、宽高 >480px、单张 <3MB、仅 JPG/PNG」，让用户换图或人工上传。返回值里含「商品填写建议」面板的真实拦因与「未自动填写」清单 |
| 提交后 180s 内未检测到成功标志 | `api_error` | 让用户查看窗口内具体提示：补全红色校验项后手动提交；若有滑块需人工完成；发布成功可在「商品管理 → 出售中」核对 |
| 商品属性自动填失败（属性区未定位 / 模型不可用） | —— | **不阻断发布**，只是该属性留空；非必填属性留空不影响提交，可由用户在窗口内手填 |
| 已有拼多多商家后台浏览器任务在进行中 | `api_error` | 提示先等待该任务结束或关闭已弹出的浏览器窗口 |
| 未找到 Chrome / Edge | `api_error` | 提示用户安装 Chrome 或 Edge |

## 环境变量

本技能为纯指令型，不执行脚本。**商品属性自动填**由 host 工具内部调用一个 OpenAI 兼容文本模型，
可用以下环境变量覆盖（不配则走内置默认值）：

| 变量 | 用途 |
|------|------|
| `PDD_TEXT_MODEL_BASE_URL` | 模型服务地址（OpenAI 兼容 `/v1`） |
| `PDD_TEXT_MODEL_API_KEY` | 模型 API Key |
| `PDD_TEXT_MODEL` | 模型名 |

账号凭证由 host 工具从凭证库读取并**在浏览器内注入 Cookie**，日志与返回值均已脱敏，**技能侧不接触 Cookie**。
