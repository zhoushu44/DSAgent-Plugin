## 一、本次新增能力

### 1. 成分列表组件（材质成分）

童装家居服（catId=15021）的「材质成分」不是下拉框，是独立的成分列表组件。

**页面结构**：
```html
<div data-testid="beast-core-form-item" id="basic.propertys.15.value">
  <span class="Form_itemRequired">*</span><label>材质成分</label>
  <button data-testid="beast-core-button">
    <span class="IngredientList_addBtn__2njWF">添加材质成分(0/7)</span>
  </button>
</div>
```

**四步流程**（`steps/helpers/fill-ingredient-list.mjs`）：
1. 点「添加XXX(N/M)」按钮
2. 等面板出现（`IngredientList_checkItem`）
3. 按文字点对应 checkbox 的 label
4. 点「确定(N/M)」按钮

**21 个可选成分**：棉 / 麻 / 蚕丝 / 羊毛 / 羊绒 / 其它 / 亚麻 / 氨纶 /
涤纶（聚酯纤维）/ 粘胶纤维 / 莫代尔纤维 / 醋酯纤维 / 锦纶 / 竹浆纤维 /
天丝（莱赛尔纤维）/ 竹纤维 / 腈纶 / 竹炭纤维 / 尼龙 / 铜氨纤维 /
棉麻混纺 / 棉涤混纺 / 聚丙烯纤维 / 氯纶（聚氯乙烯纤维）/ 维纶 / 羊驼绒

### 2. 识别方式

```js
const sel = item.querySelector('[data-testid="beast-core-select"]')
const ingredientEl = item.querySelector('[class*="IngredientList"]')

if (!sel && !ingredientEl) continue

if (ingredientEl) {
  // 成分列表型
  out[label] = { formItemId: id, mode: 'ingredient', ... }
  continue
}
// 否则走下下拉框逻辑
```

- 有 `IngredientList` → 成分列表流程
- 有 `beast-core-select` → 下拉框流程
- 都没有 → 跳过

组件名 `IngredientList` 来自 React CSS Module 命名（`组件名_用途__哈希`），
哈希会变但组件名不变，所以 `[class*="IngredientList"]` 匹配稳定。

### 3. 虚拟列表属性用输入筛选

「上市时节」等选项特别多的属性，下拉是虚拟列表（`ST_virtualList`），
只渲染可见的几项，直接找后面的选项找不到。

修法：按模板选项数量判断，> 20 个就走输入筛选。
```js
const optCount = tplByLabel.get(label)?.options?.length || 0
const needSearch = /品牌|型号|货号/.test(label) || optCount > 20
```

不探测页面，不算多一次点击。

## 二、性能优化

### 优化 1：类目确认 17.5s → 0.6s

**旧写法**：
```js
await page.waitForFunction(() => !document.querySelector('input[data-tracking-viewid="key_words_search"]'), { timeout: 15000 })
await sleep(2500)
```
等搜索框从 DOM 消失，但那个 input 只是被隐藏、不删除 → 每次等满 15 秒超时。

**新写法**：
```js
await page.waitForFunction(() => {
  const btn = document.querySelector('button[data-tracking-click-viewid="cate_confirm"]')
  return !btn || btn.offsetParent === null
}, { timeout: 6000 })
await sleep(400)
```

**实测**：S06 0.6s / S07 2.1s / S09 0.8s

### 优化 2：属性回填确认 1.5s → 0.1s

**旧写法**读 form-item 的 `innerText`，里面包含 label 文字和 placeholder「请选择」
→ 永远判为未填 → 等满 1.5 秒。

**新写法**直接读 input 的 value：
- 有 input → 任一 value 非空即成功
- 成分列表 → 看按钮计数 (N/M) 里 N > 0

轮询间隔 250ms → 100ms。

### 优化 3：属性重扫改成「按需」

**旧写法**每填一个属性前都重扫整个属性区，17 次。

**新写法**先看当前 labelMap 里有没有这个 label：
- 有 → 直接填，不重扫
- 没有 → 才重扫（级联新出现的属性，如「材质成分」）

实测 15 个属性全部 `hasNow=true`，都不重扫。

## 三、已验证不可行的优化

### 属性两列并发 —— 不可行

同时点开两个下拉，面板都挂在 body 上：
```
panelCount: 2                    ← 两个面板同时存在
填「面料俗称」→ 选到「无品牌/无注册商标」   ← 品牌的值
填「适用性别」→ 选到「金丝绒」            ← 面料的值
```

**面板互相串值，必须串行。**

### SKU 一次 evaluate 写整表 —— 不可行

```
一次 evaluate 写 6 行 × 4 个值：
  行0: ["100", "", "", "TESTA"]   ← 库存和编码留下，价格全空
  行1: ["101", "", "", ""]
```

**平台价格联动校验（拼单价 < 单买价），同时设多个值 React 只处理最后一个 → 必须逐个写。**
