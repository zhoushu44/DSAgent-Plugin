## 二、踩过的坑（按严重程度排序）

### ★★★ ① 主图上传后计数不变（最高频问题）

**现象**：`uploadFile()` 返回成功，但页面显示「上传图片 (0/10)」，点下一步报「请上传商品轮播图」。

**根因**：`uploadFile` 只设置 `input.files`，React 收不到变化事件。

**修法**：
```js
await fi.uploadFile(...imgs)
await page.evaluate(() => {
  const inp = document.querySelector('section[class*="goodsCarousel_uploadImgEnter"] input[type="file"]')
  inp.dispatchEvent(new Event('input', { bubbles: true }))
  inp.dispatchEvent(new Event('change', { bubbles: true }))
})
// 重试前必须清空，否则同文件会被浏览器忽略
await page.evaluate(() => { document.querySelector('...input[type=file]').value = '' })
```

### ★★★ ② 类目搜索不出结果

**现象**：输入类目名，下拉不出现 / 出现但点选后 cat_id 不变。

**三个必要条件**：
1. **搜索词去掉 `>` 和 `/`**
   ```
   女装/女士精品 > T恤 > T恤  →  女装女士精品T恤T恤
   ```
2. **输入后必须点一下输入框**才触发下拉
   ```js
   await inp.click()
   await inp.evaluate(el => {
     el.dispatchEvent(new MouseEvent('mousedown', { bubbles: true }))
     el.dispatchEvent(new MouseEvent('mouseup', { bubbles: true }))
   })
   ```
3. **点完等 1 秒**，再校验确认按钮的 `data-tracking-params` 是否含目标 cat_id

**选择器**：
```
搜索框      input[data-tracking-viewid="key_words_search"]
搜索结果    li[class*="SPP_searchItem"]  （点第 1 个）
确认按钮    button[data-tracking-click-viewid="cate_confirm"]
```

### ★★★ ③ SKU 表合并单元格列错位

**现象**：女装多色多码时，第 2 行开始价格填错列（100 填到拼单价，29.9 填到单买价），报「单买价至少比拼单价高1元」。

**根因**：「颜色」列 `rowspan` 跨行，后续行的 `td[0]` 是尺码不是颜色，td 索引整体偏移。

**修法**：按 `rowspan/colspan` 推算**逻辑列号**
```js
const pending = new Map()   // col -> { td, left }
const grid = []
for (const tr of trs) {
  const tds = [...tr.querySelectorAll('td')]
  const map = new Map()
  let col = 0, ti = 0
  while (ti < tds.length || pending.get(col)?.left > 0) {
    const p = pending.get(col)
    if (p && p.left > 0) { map.set(col, p.td); p.left--; col++; continue }
    const td = tds[ti++]
    const cs = td.colSpan || 1, rs = td.rowSpan || 1
    for (let k = 0; k < cs; k++) {
      map.set(col + k, td)
      if (rs > 1) pending.set(col + k, { td, left: rs - 1 })
    }
    col += cs
  }
  grid.push(map)
}
// 用表头文字找列号，再用 grid[i].get(col) 取 td
```

**实测表头**：
- 女装：`0=颜色 1=尺码 2=库存 3=拼单价 4=单买价 5=预览图 6=规格编码 7=状态`
- 纸杯：`0=容量 1=库存 2=拼单价 3=单买价 4=预览图 5=规格编码 6=状态`

**验证过的行数**：3 / 4 / 6 / 10 / 12 行全部正确。

### ★★★ ④ 规格只生成 1 行 SKU

**现象**：填了 2 个规格值，SKU 只有 1 行。

**根因**：勾选框实际是 `input[type="checkbox"]`，不是 `div.CBX_square`（那是视觉方块）。

**修法**：
```js
// 每个规格值 = 一行，按索引配对
const pickChecks = [...box.querySelectorAll('input[type="checkbox"]')]
const pickInputs = [...box.querySelectorAll('input')].filter(e =>
  ['text','','number'].includes(e.type) && /自定义/.test(e.placeholder || ''))
// 第 i 个值 → pickChecks[i] + pickInputs[i]
// ★ 顺序：先输值，再勾选
```

**注意**：`CBX_groupDisabled` 是正常态，不要排除。

**现象**：点「添加规格类型」报 `NOT_FOUND`。

### ★★ ⑥ 尺码表身高/体重填不上

**现象**：输入框只有一个，填了「160-165」无效。

**根因**：必须先勾表头的「区间值」，勾完每行才变成两个输入框（下限/上限）。

### ★★ ⑦ 必填项判断全 false

**现象**：模板里 `required` 全是 false，但页面上明明有红星。

**根因**：`*` 号在 `span.Form_itemRequired` 里，**不在 label 文本前缀**。

```html
<span class="Form_itemRequired_xxx">*</span><label>成分含量</label>
```

**修法**：
```js
const isReq = !!it.querySelector('span[class*="Form_itemRequired"]')
```

**重要发现**：模板 API（`/template/mall`）返回 15 条属性，「材质」「成分含量」**不在其中**，是选完「面料俗称」后**动态插入**的 `propertys.15/16`。

→ 必须在填完模板属性后**再扫一次页面**补新增必填项。

## 五、限流与风控

### `/template/mall` 限流（40002）

**这是账号级 + 平台级硬限流**，触发后：
- Node 通道 → 40002
- 浏览器通道 → 40002
- 换账号 → 仍然 40002

**只能等冷却**（30 分钟 ~ 次日）。

**预防**：
1. 拉模板前用 `pdd-antiban.reserveSlot()` 拿配额
2. **第一次 40002 就停**，不要重试
3. 不要用页面内裸 fetch（没有签名，最容易触发）

### Cookie 会话（43001）

**Node 通道要求凭证库 cookie 有效**。若浏览器已登录但 Node 报 43001：
1. 从浏览器 CDP 取实时 cookie
2. `invalidateStoreCookieCache(shopKey)` 清缓存
3. 或直接用 `forceBrowser: true`

**注意**：`request()` 遇到 43001 会**自己启动浏览器自愈**，如果已有浏览器占着 profile 会撞锁失败。传 `__healed: true` 可跳过。

## 六、操控浏览器的正确姿势

### 不要做的事

```powershell
Get-Process chrome | Stop-Process -Force    # ❌ 会杀掉用户正在看的窗口
```

### 应该做的事

```js
// 1. 扫端口找已有浏览器
const ports = execSync('Get-NetTCPConnection -State Listen ...')
for (const pt of ports) {
  const r = await fetch(`http://127.0.0.1:${pt}/json/version`)
  const j = await r.json()
  if (/Chrome/i.test(j.Browser)) {
    const b = await puppeteer.connect({ browserURL: `http://127.0.0.1:${pt}` })
    if ((await b.pages()).some(x => /mms.pinduoduo.com/.test(x.url()))) return b
  }
}

// 2. 没有才新开
await launchStealth(shopKey, puppeteer)
```

### 登录态保存

**账号连接器不保存 cookie**，登录成功后必须：
```js
const cdp = await page.target().createCDPSession()
const { cookies } = await cdp.send('Network.getCookies', { urls: ['https://mms.pinduoduo.com'] })
// 写回凭证库
```

然后**不要关窗口**，否则 cookie 丢失。

## 十、三个通用填充组件（核心资产）

### ① `helpers/fill-by-group.mjs` —— 勾选框 + 输入框按组配对

覆盖所有「点选 + 输入」组合，**预设值和自定义值通吃**。

```js
fillByGroup(page, dimName, values, dim)
```

三种模式：

| 模式 | 触发条件 | 页面结构 | 例子 |
|---|---|---|---|
| `preset` | 已有组的值等于目标值 | `.package-item-container` + `.check-wrapper` | 女装颜色（115 个预设）|
| `custom` | 值不在预设里 | `.custom-input-container` + 输入框 | 纸杯容量 |
| `bare-input` | **没有任何组容器** | 裸 `<input placeholder="选择或输入主色">` | 运动鞋颜色 |

**关键规则**（用户明确要求）：

```js
// ① 第 i 个值 → 第 i 组，绝不共用第 1 个输入框
const inp = inputs[index]        // ✅
const inp = inputs[0]            // ❌ 错

// ② 先输值，再勾选
writeValue(inp, val)  →  cb.click()

// ③ 组内第 1 个 text input = 规格名；第 2 个 = 备注，不写
const nameInput = textInputs.filter(e => !/备注|说明|note/.test(e.placeholder))[0]
```

### ② `helpers/size-table-fill.mjs` —— 通用尺码表

兼容服装尺码与运动鞋码，**自动判断切哪个标签页**。

```js
fillSizeTable(page, dimName, values, { tabHint })
```

标签页推断规则：

| 目标值形态 | 切到 |
|---|---|
| `M` / `L` / `XL` / `均码` | 中国码 |
| `160/84A`（三段式）| 中国码 |
| `40` / `42.5`（纯数字）| **欧码** |
| 模板 `tabHint` 指定 | 优先用它 |

流程：切标签页 → 勾表头「区间值」→ 逐个值点 checkbox。

### ③ 模板 `type` 分派（step11）

```js
switch (dim.type) {
  case 'text':       fillByGroup
  case 'checkbox':   fillByGroup
  case 'size-table': fillSizeTable({ tabHint })
  case 'none':       跳过
}
```

**新类目只需在 template.json 标对 `type`，step11 完全不用改。**

## 十七、稳定性修复（页面重取 refetch）

### 问题

```
Attempted to use detached Frame 'xxx'
Execution context was destroyed
```

发布页在加载过程中会自己导航/重建，代码持有的 `page` 引用会失效。

### 修法

每次关键操作前重新从 `browser.pages()` 取当前页：

```js
async function refetch(re = /mms\.pinduoduo\.com/) {
  for (let i = 0; i < 25; i++) {
    const ps = await browser.pages()
    const hits = ps.filter(x => !x.isClosed() && re.test(x.url()) && !/goods_add\/success/.test(x.url()))
    if (hits.length) { p = hits[hits.length - 1]; await p.bringToFront(); return p }
    await sleep(250)
  }
  return p
}
```

**已加在 5 个位置**：主图前、主图后、标题前、类目前、步骤4 前。

## 二十、价格库存写入顺序（2026-11-16）

### 必须「先写单买价，再写拼单价」

**平台联动校验：拼单价 必须 < 单买价**

```
❌ 先写拼单价 545
   → 此时单买价还是空
   → React 判定非法
   → 直接清空拼单价
   → 提交报「第1行规格的拼单价必须大于0」

✅ 先写单买价 546
   → 再写拼单价 545
   → 两个都保留
```

**实测证据**：

```
顺序 A（拼单价先）：
  写 11.1 → 回读 ["111","","22.1","TEST"]   ← 拼单价空了

顺序 B（单买价先）：
  写 22.1 → 写 11.1 → 回读 ["111","11.1","22.1","TEST"]  ← 全在
```

### 必须每写一个值回读

```
同一次 page.evaluate 里连续写 4 个值：
  第1个 ✅  第2个 ❌  第3个 ✅  第4个 ✅
  （React 重渲染把第2个冲掉了）

每写一个 → evaluate 返回 → 再进页面 → 重新查 DOM → 写下个：
  4 个全部 ✅
```

### 行内定位用「第 N 个 text input」

**不能用表格列号**——规格列有 rowspan 合并，td 索引会错位。

```
表头顺序 → input 顺序：
  库存 → 拼单价 → 单买价 → 规格编码 → 商品编码
（规格列只有文字无 input；预览图是 file input，已过滤）
```

### 回读不一致只警告

不同类目 SKU 表的 rowspan/colspan/表头结构差异极大：

| 类目 | 表头列数 | 规格列合并 |
|---|---|---|
| T恤 | 8 | 颜色 rowspan=3 |
| 休闲裤 | 8 | 颜色 rowspan=2 |

## 价格三角规则（2026-11-22 实测，真实上架 goodsId=1032957069103 验证）

提交时平台强校验「参考价应大于商品最大单买价」，而本技能校验器要求「拼单价 < 单买价」。
三者必须同时满足，缺一会被不同环节拦截：

\\\
参考价（product.price） > 单买价（skus[i].price） > 拼单价（skus[i].multiPrice）
\\\

实测通过的组合：参考价 19.9 / 单买价 12.9 / 拼单价 11.9。

**踩坑记录**（三次被拦的真实报错）：
1. 参考价 9.9、单买价 10.9 → 页面错误面板：「参考价应大于商品最大单买价」（step16 提交被拦）
2. 参考价 19.9、单买价 10.9、无 multiPrice → 校验器报「拼单价 19.9 必须小于单买价 10.9」
   （根因：multiPrice 缺省回落 topPrice=product.price=19.9，与单买价倒挂）
3. 三角齐全 → ✅ 上架成功

**规则**：组商品时必须显式给 skus[i].multiPrice，且保持 参考价 > 单买价 > 拼单价。
另：错误面板的具体文本在返回 payload 的 steps[16].required.missing[].text 里，
顶层 text 只显示「页面错误面板(N)」——排查必填问题先看 payload。
