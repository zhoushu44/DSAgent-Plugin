# 通用指标与证据使用规则

本知识只供明确引用它的方法包在 AI 分析节点查询。它负责约束如何理解数据、完成可复核计算并形成业务证据，不负责取数或清洗。当前方法包及其引用的更具体知识优先于本知识。

## 指标消费

### 当前编排中的职责边界

1. 获取经营数据节点根据方法包的数据要求，从当前已绑定店铺读取授权数据。
2. 整理分析数据节点完成字段映射、清洗、质量检查并生成结构化数据包和 Excel。
3. AI 分析节点使用上游字段和质量说明，并依据当前方法包及冻结知识中的明确规则计算指标、聚合、排名和分层。
4. 报告节点汇总已经形成的分析结论，不新增数据事实，也不重新计算指标。

源平台直接提供的指标是原始证据。AI 依据当前方法明确规则形成的计算结果也是可消费证据，但必须记录公式或规则、输入字段、对象范围和结果。不得执行脚本、根据字段名称猜算法或临时发明判断阈值。

### 时间与比较口径

- 业务时区统一使用 `Asia/Shanghai`。
- “近 N 天”“最近 N 天”“过去 N 天”默认指截至昨天的 N 个完整自然日；只有用户明确要求“包含今天”时才允许使用今天的数据。
- 明确指定起止日期时按闭区间处理，开始日和结束日都计入。
- 当前周期与对比周期必须天数相同，并尽量保持相同星期结构。周期不等长或包含未完成自然日时，不得直接给出环比结论。
- 报告和分析结果必须写明实际数据起止日期，不能只写“最近一段时间”。

### 当前标准字段的理解

以下口径只解释当前店铺字段目录中已经存在的字段。是否可用于某次分析，以本次结构化数据包实际交付的字段和来源说明为准。

| 业务字段 | 当前含义 | 使用限制 |
|:---|:---|:---|
| 访客数 | 店铺访客或商品访客 | 必须同时说明对象粒度，店铺访客不能作为单品访客证据 |
| 支付买家数 | 完成支付的买家数 | 用于解释成交人数；不得与订单量混用 |
| 订单量 | 支付订单数 | 一个买家可能对应多个订单，不能替代支付买家数 |
| 成交金额 | 当前来源提供的支付金额/成交金额 | 使用前确认来源和对象粒度，不自动等同于扣除退款后的净收入 |
| 支付转化率 | 来源字段 `payRate` 映射为支付转化率 | 直接消费上游值；不得把不同粒度或不同周期的转化率简单平均 |
| 客单价 | 来源字段 `payPct` 映射为客单价 | 直接消费上游值；没有支付买家数时不自行反推 |
| 退款金额 | 成功退款金额 | 只能说明已退款规模，不能单独证明商品质量问题 |
| 退款率 | 来源字段 `payAmtRfdRate` 映射的金额退款率 | 不得与 `sucRefundRate` 成功退款率混用 |
| 内容访客数 | 内容渠道带来的访客数 | 只能说明内容流量规模，不能单独证明内容带来成交 |
| 推广消耗 | 推广来源记录的花费 | 必须与相同对象、相同归因口径和相同周期的推广产出比较 |
| 推广成交金额 | 推广来源归因的成交金额 | 不等于全店或商品全部成交金额 |
| 推广 ROI | 来源字段 `roi` 映射的投产比 | 仅用于评价当前推广归因口径下的投放效率，不等同于利润率或经营 ROI |

`经营 ROI`、销售占比、加购率和千次展现花费不是平台对所有编排稳定保证的原始字段。只有当前方法明确给出公式且输入字段齐全时，AI 才能计算和使用，并保留计算依据。

### 粒度、关联与聚合

- 每条结论必须与数据粒度一致：店铺、商品、类目、推广计划和日期不能互相替代。
- 店铺级推广花费不能直接分摊为商品级花费；推广表缺少可靠商品标识时，必须记录关联缺口。
- 多表关联前必须先确认连接键和两侧粒度。关联导致重复行、对象数增加或金额被放大时，相关结论不可使用。
- 金额、人数和订单数可以在同口径下求和；率值、占比和客单价不得跨行直接求和。
- 跨日或跨对象汇总率值时，使用原始分子、分母和当前方法明确公式重新计算；没有分子、分母或确定公式时，不得对日率做简单平均。
- 缺失、未知、未采集和无法关联都不等于数值 0。只有上游明确返回 0，才能写“零成交”“零花费”等结论。

## 通用预警基线

这里的“预警基线”是通用的判断顺序，不提供跨店铺固定数值阈值。

### 判断与下钻规则

- 优先使用方法包声明的判断规则、店铺目标、盈亏线和本次分析按规则生成的异常标签。
- 没有业务目标时，只能根据同对象的历史变化、结构占比和规模影响排列核查优先级，不能把通用示例阈值写成店铺盈亏线。
- 发现异常时先确认周期、粒度、样本规模、缺失字段和来源口径，再讨论业务原因。
- 连续变化不等于因果关系。没有活动、价格、推广、库存、内容或售后证据时，只能给出待核查方向。
- “加预算”“停推”“下架”等强动作必须同时具备明确对象、有效周期、投入规模、产出证据和适用判断标准；证据不足时只能建议观察、补数或小范围验证。

## 输出约束

### AI 输出要求

- 每个 finding 必须区分“数据事实”“业务解释”和“行动建议”。
- 每个 finding 必须引用实际存在的证据字段和值，并保留 `evidence_ids`；使用本知识时同时保留对应 `knowledge_refs`。
- 数据不足、字段缺失、口径冲突或关联失败必须进入 `missing_evidence` 或限制说明，不能静默忽略。
- 不得引用本次数据和所选知识之外的行业均值、竞品表现或平台规则作为事实。
- 不得因为知识中提到某个指标，就假定本次数据一定包含该指标。
