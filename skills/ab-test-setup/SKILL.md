# A/B 测试与实验设计

设计**统计有效、可下结论**的实验。核心不是"跑个测试看看"，而是**在开跑之前就把结论的判据锁死**——否则你得到的只是"看起来赢了"。

## 前置条件

设计任何测试之前，先拿到这四个输入；缺一个就先补齐，不要开始：

1. **基线转化率**（当前的真实数字，不是感觉）
2. **流量规模**（该页面/该商品每天多少访客或曝光）
3. **最小可检测效应 MDE**（多小的提升才值得你动手）
4. **现有工具与前测历史**（用什么跑、这个位置以前测过什么）

**判断能不能测的铁律**：用下面的速查表先估样本量，再用流量算时长。**如果算出需要 3 个月以上，这个测试就不要做**——改成更粗的改动或直接换策略。

**电商场景的额外前提**：

- **主图类测试**：确认平台允许你更换主图（部分平台的类目审核期不允许频繁改主图），并确认排期避开大促与活动期。
- **价格/优惠类测试**：确认不违反平台价格规则（虚构原价属违规），且不同版本不能造成实际成交价不一致。
- **详情页/标题类测试**：确认被测流量来源一致（自然搜索进来的和直通车进来的转化率完全不同，混在一起测等于白测）。

## 工作流

1. **写假设**。用固定句式，缺任何一项都不算假设：`因为【观察/数据】，我们相信【改动】会对【人群】造成【预期结果】。当【指标】达到 X 时，我们认为假设成立。`
2. **定设计与变量**。选 A/B 还是 A/B/n；**一次只测一个变量**——同时改标题和主图，赢了也不知道是哪个赢的。
3. **算样本量与时长**。用速查表估每版所需样本 → 再算 `时长 =（每版所需样本 × 版本数）÷（日均流量 × 转化率）`。**最少跑 1–2 个完整业务周期（通常 1–2 周）。** 算出来超过 3 个月就放弃这个测试。
4. **选三类指标 + 做版本**。主指标唯一、直接对应假设；次指标解释为什么赢；护栏指标（退款率、客单价、复购）不能被搞坏。对照版保持原状不动，实验版改动要**足够大以致可被检测**但**忠于假设**，并记录截图与理由。
5. **预注册再开跑**。把假设、样本量、时长、主指标、判定标准**先写下来**再启动——这是防"事后解释"的唯一手段。
6. **按纪律跑完**。不偷看、不中途改版本、不引入新流量源、不因为"我觉得我知道了"提前结束。
7. **判读并归档**。跑满样本量后按下面「判读六问」逐条过，把结论与学到的东西写进实验库，避免重复测试同一个位置。

## 判读六问（跑完之后）

1. **样本量到了吗？** 没到 → 结论只能算初步。
2. **统计显著吗？** 95% 置信 ≈ p < 0.05。
3. **效应量有意义吗？** 拿它跟你的 MDE 比，并折算业务收益。
4. **次指标一致吗？** 支持主指标还是有意外？
5. **护栏有恶化吗？** 退款、客单价、复购有没有变差？
6. **分群有差异吗？** 新客 vs 老客 / 移动 vs PC / 自然 vs 付费。

### 结果解读对照

| 结果 | 结论 |
|---|---|
| 显著赢 | 实施该版本 |
| 显著输 | 保留对照，但**要搞清为什么输**（这是最有价值的信息） |
| 无显著差异 | 流量不够，或**改动太温和**（加大力度重测） |
| 信号混乱 | 深挖，通常是分群问题 |

## 错误处理

- **样本量算出来远超流量承受力**：不要硬跑。降低目标（只测更大胆的改动）、改用更接近转化的指标，或直接放弃测试改做判断——**没把握的测试比不做测试更贵**（占用流量、制造假信心）。
- **中途发现实现错误或流量分配不均**：立即停止并作废本次数据，修复后重新计时。**不要"边跑边修"**。
- **跑完了但结论不显著**：如实报告"无显著差异"，不要挑分群或挑指标找出一个赢的——**那叫数据挖掘，不叫结论**。

## 核心纪律

### 假设框架（唯一格式）

```
因为 [观察/数据]，
我们相信 [改动]
会对 [人群] 造成 [预期结果]。
当 [指标] 达到 X 时，我们认为假设成立。
```

**弱假设**："换个主图可能点击率会高一点。"
**强假设**："因为竞品在同类目都用场景图而我们在用白底，我们相信把主图换成场景图会让新客点击率提升 15% 以上。我们以搜索列表曝光到点击的转化率来衡量。"

### 样本量速查表（95% 置信 / 80% 功效）

| 基线转化率 | 提升 10% | 提升 20% | 提升 50% |
|---|---|---|---|
| 1% | 150k/版 | 39k/版 | 6k/版 |
| 3% | 47k/版 | 12k/版 | 2k/版 |
| 5% | 27k/版 | 7k/版 | 1.2k/版 |
| 10% | 12k/版 | 3k/版 | 550/版 |

**先看这张表再谈时长。** 主图点击率通常比页面转化率高得多（常常 3–10%），所以主图测图反而是**电商里少数能测得动的实验**。

### 时长公式

```
时长 =（每版所需样本 × 版本数）÷（日均流量 × 转化率）

下限：1–2 个完整业务周期（通常 1–2 周）
上限：不要跑太久（新奇效应 + 外部因素污染）
```

### ⚠️ Peeking 问题（最高频的致命错误）

**没跑满样本量就偷看，看到显著就停**，会带来：假阳性、被夸大的效应量、错误决策。

**解法**：预注册样本量并坚持到底；确需中途看就用序贯检验（sequential testing）；**信任流程**。

## 电商场景的测试对象

| 测什么 | 主指标 | 常见护栏 | 注意 |
|---|---|---|---|
| **主图/首图** | 曝光→点击率（CTR） | 加购率、退货率 | 平台换图限制；避开大促 |
| **详情页模块** | 访问→加购率 | 停留时长、退款率 | 分片测试，别整页改 |
| **标题/关键词** | 搜索曝光→点击 | 转化率、退货率 | 流量来源要一致 |
| **价格/优惠** | 转化率、客单价 | **毛利、退款率** | 不得虚构原价（合规） |
| **页面/表单流程** | 完成率 | 下游质量（激活率） | 服务端测试无闪烁 |

> **主图测图的正确姿势**：一次只改一个变量（换机位 / 换场景 / 换卖点表达），**保持其他全部一致**。想测"整体风格"差异，就做**多组独立实验**，而不是在一组里混多种风格——混在一起赢了也归因不了。

## 可直接用

### 测试计划模板

```
# A/B 测试：[名称]

## 假设
[用假设框架写完整]

## 设计
- 类型：A/B 还是 A/B/n
- 时长：X 周
- 样本量：每版 X
- 流量分配：50/50

## 版本
- 对照（A）：[现状描述 + 截图]
- 实验（B）：[具体改动 + 截图 + 为什么它会赢]

## 指标
- 主指标：[指标 + 定义]
- 次指标：[列表]
- 护栏：[列表]

## 分析与判定
- 成功标准：[什么算赢]
- 分群计划：[新老客 / 设备 / 来源]
```

### 上线前检查清单

- [ ] 假设已文档化
- [ ] 主指标已定义
- [ ] 样本量已算
- [ ] 时长已估
- [ ] 版本实现正确、已 QA
- [ ] 埋点已验证
- [ ] 相关人已知会
- [ ] **预注册已写下（防事后解释）**

### 跑测试期间

**要做**：监控技术问题 · 检查分群质量 · 记录外部因素（大促、竞品动作、平台改规则）
**不要做**：偷看并提前停 · 中途改版本 · 引入新流量源 · 因为"我觉得我知道了"而提前结束

## 与其它技能的配合

| 环节 | 用哪个技能 |
|---|---|
| 造出多个待测版本（主图/详情页） | `image-prompt-guide` |
| 从评论里找该测什么（痛点/未满足需求） | `customer-voice-analyzer`、`product-reviews` |
| 找该测哪些关键词/标题词 | `keyword-assistant` |
| 客户分层，判断分群测试对象 | `customer-rfm-analyzer`、`sycm-customer` |
| 把结果做成报告 | `data-report`、`xlsx` |

> **缺口提醒**：本技能负责**设计与判读**，不负责**自动分流与埋点采集**。实际分流需要你自己的平台工具或 A/B 系统；本技能产出的是可直接配置进任何工具的**实验规格**。
