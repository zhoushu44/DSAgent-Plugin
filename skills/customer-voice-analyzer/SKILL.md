# Customer Voice Analyzer（买家之声分析）

## 前置条件

- 已取得评论样本（走 `product-reviews` / `product-wdj`，或用户提供的文件），且**覆盖全星级**。
- 样本量建议 100–200 条；样本不足 30 条时，结论只能作为线索，必须在报告中标注置信度低。
- 计算提及率前先确定总样本数，并剔除明显重复、模板化、与商品无关的评论。

## 工作流

1. **确认样本**：核对条数、星级分布与规格覆盖，不足则说明偏差。
2. **打维度标签**：按 6 个维度（人群 / 场景 / 优点 / 痛点 / 未满足需求 / 购买动机）逐条标注，一条可命中多维。
3. **量化排序**：统计每条的提及数与提及率，按频次降序排列。
4. **套用阈值**：痛点 >10% 判为关键缺陷，优点 >15% 判为已验证卖点，未满足需求 >5% 判为迭代机会。
5. **输出结论**：产出 6 张维度表 + 迭代缺口分析（改进项 + 文案钩子 + 人群场景矩阵）。

## 错误处理

- 只有好评或样本严重偏斜：明确拒绝给出"已验证"结论，先说明采样偏差并建议补采。
- 单条极端差评：不得当作系统性问题，需说明"仅个案，未形成模式"。
- 提及率处于阈值边缘（如痛点 8–12%）：标注为"可能关键"，不要强行下确定结论。

把原始商品评价转化为结构化的经营情报，回答两个问题：
**「我要怎么改产品？」** 与 **「我的文案该说什么？」**

## 取数（Step 1）

本技能**不自带采集脚本**，取数走已有的兄弟技能，或直接用用户给的数据：

| 数据源 | 用什么 | 说明 |
|--------|--------|------|
| 淘宝 / 天猫商品评价 | `product-reviews` 技能 | 传入商品 ID 或链接，导出 JSON/CSV |
| 问大家（买家问答） | `product-wdj` 技能 | 补充「购买前最关心什么」的意图信息 |
| 用户已有文件 | 直接读 | CSV / JSON / Excel 均可 |

**采集口径要求：**

1. 目标 100–200 条，**必须覆盖全星级**（1–5 星都要），不要只抓好评
2. 若有多个 SKU / 规格（尺寸、颜色、型号），按规格分层采样
3. 每条至少保留：评论文本、星级、SKU/规格、是否追评、日期

> **为什么必须平衡采样**：5 星验证卖点；1–2 星暴露致命缺陷；
> **3 星往往信息量最大**——「差一点就满意了」的地方就是改进路线图。

## 6 维语义映射（Step 2）

把每条反馈打上维度标签（一条评论可同时命中多个维度）：

| 维度 | 捕获什么 | 示例 |
|------|---------|------|
| **人群画像** | 谁在买？身份、经验水平、购买背景 | 「新手宝妈」「给长辈买礼物」「专业厨师」 |
| **使用场景** | 在哪、何时、怎么用 | 「家用健身」「冬季露营」「通勤」「孩子生日会」 |
| **优点（Pros）** | 被验证的卖点，顾客真心喜欢 | 「电机意外地安静」「刚好能登机」 |
| **痛点（Cons）** | 缺陷、质量抱怨、体验问题 | 「两周后盖子漏水」「说明书看不懂」 |
| **未满足需求** | 用户希望有但还没有的功能——迭代路线图 | 「希望有大码」「要有定时器就完美了」 |
| **购买动机** | 促成本次下单的钩子——转化话术源头 | 「刷短视频看到的」「要 30 元以内的礼物」「从 X 品牌换过来」 |

## 量化排序（Step 3）

每个维度内按提及频次排序，把信号从噪声里分离出来。

对每条发现计算：

- **发现（Finding）** = 具体洞察（如「盖子漏水」）
- **提及数（Mention Count）** = 提到该发现的评论条数
- **提及率（Mention Rate %）** = 提及数 / 总评论数 × 100%
- **代表性原话（Key Quote）** = 最有代表性的一条原文摘录

**优先级判定阈值：**

| 维度 | 阈值 | 结论 |
|------|------|------|
| 痛点 | 提及率 > 10% | 关键缺陷，**必须修** |
| 优点 | 提及率 > 15% | 已验证卖点，**放大到营销里** |
| 未满足需求 | 提及率 > 5% | 值得评估的迭代机会 |
| 购买动机 | 高频出现 | 直接作为投放钩子与 listing 文案角度 |

## 输出格式

### 6 张维度表（每维一张，按提及频次降序）

| 排名 | 发现 | 提及数 | 提及率 % | 代表性原话 |
|------|------|--------|----------|-----------|
| 1 | [发现] | [N] | [X]% | 「[原文摘录]」 |
| 2 | [发现] | [N] | [X]% | 「[原文摘录]」 |

### 迭代缺口分析（Iteration Gap）

```
商品：[商品 ID / 名称]
分析样本：[N] 条评价，覆盖 [N] 个规格

产品改进优先级（Top）：
1. [痛点] — 提及率 X% — 改法：[具体建议]
2. [未满足需求] — 提及率 X% — 改法：[具体建议]
3. ...

核心文案钩子（来自已验证优点 + 购买动机）：
1. [钩子] — 依据：[优点/动机]，提及率 X%
2. [钩子] — 依据：[优点/动机]，提及率 X%
3. ...

人群 × 场景矩阵：
- 主要买家：[人群] 用于 [场景]
- 次要买家：[人群] 用于 [场景]
```

## 常见坑

| 坑 | 正确做法 |
|----|---------|
| 只读 5 星好评 | 3 星含最丰富的「差一点」信息；1–2 星暴露劝退点 |
| 把所有提及等同看待 | 30% 的人提到的缺陷与 2% 提到的，性质完全不同——必须量化 |
| 忽略规格差异 | 不同尺寸/颜色/型号痛点可能完全不同，必要时按规格分别分析 |
| 只给结论不给原话 | 发现必须配原文摘录——原话就是现成的文案素材，还提供可信度 |
| 被少数声音带偏 | 单条情绪化的 1 星差评 ≠ 系统性问题，要看跨评论的模式 |

## 快速参考

- **6 个维度**：人群画像、使用场景、优点、痛点、未满足需求、购买动机
- **样本量**：100–200 条，覆盖全星级、平衡采样
- **关键阈值**：痛点 >10% = 关键缺陷；优点 >15% = 已验证卖点；未满足需求 >5% = 迭代机会
- **核心产出**：6 张维度表 + 迭代缺口分析（产品改进项 + 文案钩子）
- **配合技能**：`product-reviews`（取评价）、`product-wdj`（取问答）、`image-prompt-guide`（把卖点钩子做成图）、`smart-compose`（把钩子写成文案）
