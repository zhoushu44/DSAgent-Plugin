# 输出契约

## 默认交付顺序

1. 一句话经营判断。
2. 店铺关键指标表。
3. 类目与商品贡献表（商品层可用时）。
4. 店铺类目与对应行业类目并排对比（行业可比时）。
5. 推广渠道对比表和计划明细表（推广层可用时）。
6. 数据缺口与影响。
7. 按优先级排列的动作建议，并说明观察周期或触发条件。

## 表达要求

- 使用自然语言业务字段，不展示接口名、内部字段、类目ID、JSON路径或程序状态。
- 报告中的数字、占比、环比和结论必须来自冻结证据包或确定性汇总。
- 店铺周期指标、首末日变化、推广周期指标和店铺/商品口径核对直接读取 `summary`；类目、商品、渠道、计划和行业对比读取对应汇总表，不得再对每日原始行求和。
- 模型可以自行生成自包含HTML并调整配色、布局，但只能组织和解释已有事实，不得重新计算、补数或改变优先级。
- 数据覆盖只能写成“本次查询/本次返回覆盖……”，不得写成“数据源自某日开始”或推断平台永久缺少更早数据。
- 动作建议默认写“动作 + 观察指标 + 复核周期/触发条件”。只有用户给出目标、历史基准、行业基准或业务约束时才能写具体数值目标；不得自行创造“降到25%”“提升到15%”之类阈值。
- 可以说明校验通过和数据存在缺口，但面向用户的正文、页脚和文件说明均不得出现证据文件名、脚本名、内部类目ID、接口字段名或处理链路。
- Excel只在用户明确要求时生成。

## HTML交付方式

- HTML只是展示形式，不是第二次分析。直接把已经确定的业务结论和表格写入最终HTML，不创建临时HTML生成器，也不在报告阶段重新汇总原始日数据。
- 如果所需汇总或比率不在 `patrol_facts.json` 中，回到确定性汇总阶段补齐后重新校验；不得在HTML代码、临时脚本或模型正文中现算。
- 长报告允许分章节追加到同一个最终文件，但只能有一个最终报告文件。完成后检查标题、正式周期、章节闭合、表格行数和禁止字段，不因排版失败重新取数或改变事实。

## 视觉要求

- 最终HTML参考“达摩盘竞品分析”的浅蓝商务配色，不复制其业务板块或数据结构。建议统一使用：页面底色 `#eef4fb` 至 `#e3edf9`、白色卡片、边框 `#d4e3f4`、正文 `#1e293b`、次要文字 `#64748b`、主蓝 `#1d4ed8`、浅蓝强调 `#dbeafe`、标签底色 `#eff6ff`；卡片使用轻量蓝色阴影。
- 目录链接、章节锚点、表头重点和关键数字统一使用蓝色系，不再使用橙色作为主视觉。页面只允许低饱和浅色背景过渡，禁止深色后台仪表盘、大面积高饱和渐变或同时混用多套主色。
- 经营指标的变化遵循电商阅读习惯：上涨或正向增幅用红色 `#dc2626`，下跌或负向增幅用绿色 `#059669`；风险、异常和动作优先级不能只靠颜色表达，必须同时保留文字或符号。
- 报告顶部依次展示店铺/周期、目录导航、4~6个核心经营指标、核心判断；用户不需要先阅读长表才能看到结论。
- 每个章节只解决一个问题。店铺与行业章节使用明显但克制的视觉分隔，并按“整体大盘 → 细分类目”顺序展示。
- 长表保持紧凑、数字右对齐、文字左对齐、风险行轻量标色；不得把每个数字做成卡片，也不得用连续大段文字代替表格。
- 优先动作使用两列任务卡或清晰分组，突出优先级、依据、观察指标和复核条件。
- 有连续趋势数据时保留原版的信息表达优势，使用简洁趋势图辅助表格；不得为了美观删掉完整类目结构、店铺与行业结构对比或关键明细。

## 类目与行业必须放在一起

行业被判断为匹配或部分匹配时，不得把“本店类目”和“行业趋势”拆成相距很远的独立章节，也不能只写行业文字结论。至少连续展示两张表：

1. `category_comparison` 类目结构并排表：第一行必须是“本店全部类目 vs 行业一级大盘”，后续再列所有已映射的细分类目，不能只展示某一个叶子类目。
2. `category_industry_daily` 逐日表：先展示本店全部类目销售额与行业一级大盘GMV，再展示所有已映射细分类目，不能只选一个叶子类目。每行固定包含日期、本店品类销售额、本店日环比、行业品类GMV、行业日环比、环比差值百分点、同向/背离或无效原因。

日环比只允许按自然日 D 对 D-1 计算。D-1 缺失、重复快照或为零时显示“不可比”及原因，禁止跨日补算。报告首页的店铺每日表也必须清楚展示销售额与日环比，不能只给周期汇总。

先用结构并排表回答“店铺经营结构和市场结构有什么差异”，再用逐日表回答“店铺是否跟上对应市场”。行业金额不能与本店金额直接计算市场份额；只有行业类目占其一级大盘的比例可以写成行业结构占比。

## 交付前硬检查

- 店铺名和周期属于本次运行。
- 正式汇总不包含基准日。
- 每个数据层的覆盖分别说明。
- 商品层缺失时没有商品、类目贡献结论。
- 推广表包含周期内所有实际投放渠道，渠道下有对应计划。
- 行业可比时存在逐日关联表；不可比时没有伪行业结论。
- 短于30天且没有连续历史证据时，零成交计划只能写“复核”，不能建议暂停、砍掉或合并。
- 没有其他店铺、固定类目、固定日期或历史报告残留。
- 没有自行设定的经营目标或阈值；所有具体目标都有来源或明确标为用户给定。
- 正文和页脚没有JSON文件名、脚本名、类目ID、接口字段或内部处理状态。
- 数据覆盖措辞限定为本次查询结果，没有把本次缺日描述成平台长期数据边界。
