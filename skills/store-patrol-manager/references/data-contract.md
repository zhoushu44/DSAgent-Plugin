# 数据契约

## 统一证据包

所有分析先生成 `patrol_evidence.json`。它是本次运行唯一的数据入口，至少包含：

- `run`：店铺、正式周期 `S~E`、查询周期 `S-1~E`、生成时间。
- `layers`：店铺、商品、推广、退款、行业各层的来源、查询状态、实际日期、缺失日期和原始记录。
- `coverage`：每层独立的完整性结论，不能相互替代。
- `category_mapping`：AI 对店铺类目与行业类目的判断及允许比较的范围。
- `warnings`：数据缺口及其对结论的影响。

报告、Excel和对话结论只能使用这份证据包及其确定性汇总，不得再次读取历史报告补数据。

行业类目映射使用可校验结构，不能只写一个无法定位来源的名称：

```json
{
  "match_assessment": {"status": "partial", "scope": "允许比较的范围"},
  "category_map": {
    "本店实际类目": {
      "industry_cate_id": "本次行业来源中的类目ID",
      "industry_cate_name": "行业类目名称",
      "match": "matched或partial",
      "note": "粒度差异和使用边界"
    }
  }
}
```

## 周期口径

- 正式周期固定为用户要求的 `S~E`。
- 日环比查询范围为 `S-1~E`；`S-1` 只作基准，不能进入周期汇总、排名、ROI或计划表现。
- 用户未说周期时先询问。相对周期默认不包含今天。
- 返回不完整时保留原请求周期，分别展示实际覆盖与缺日。

## 数据层

- 店铺层：店铺整体指标与每日趋势。
- 商品层：必须包含本店商品ID或名称、类目及商品指标；行业商品不能替代。
- 推广层：渠道和计划明细；只汇总正式周期内有投放的记录。
- 退款层：退款金额与退款率分开，不能用金额推导退款率。
- 行业层：只有当前会话原生注入、调用成功且AI确认可比时使用。

## 故障状态

内部统一使用：`complete`、`partial`、`empty`、`permission_denied`、`failed`、`not_queried`。最终面向用户改写成自然语言，不展示这些程序字段。

- 未查询不能写成缺失。
- 空结果不能写成接口故障。
- 明确失败最多重试一次。
- 某层不可用时继续交付其他有证据的分析。
