# 利润与涨价建议（margin-price-advice）

> **定位**：本规则是「商品后期」阶段做**提高利润 / 经营优化**时，各诊断技能给出**价格类建议**的
> 唯一口径来源。计算器：`../_shared/margin_price.mjs`（零依赖，可直接跑或 import）。
>
> **适用平台**：拼多多（pdd-promo / pdd-shop / pdd-works）、淘宝（taobao-promo /
> shop-promotion-diagnosis / sycm 系列）、抖音（douyin-uni-prom / douyin-shop / douyin-goods）。
>
> **不要**在正文、HTML 或临时脚本里现算这些数——一律调 `margin_price.mjs`，保证三平台口径一致。

---

## 0. 触发时机（核心：后期 + 想提利润）

**商品进入后期（已过测款 / 冷启动、已有投产数据）之后，只要用户在做「提高利润」或「优化」相关的事，
就给涨价安全垫建议。** 利润低**不是门槛**，它只决定**优先级**：

| 优先级 | 情形 | 动作 |
|---|---|---|
| 🔴 **高** | 后期 + 毛利率 ≤20%，**或** 净ROI < 保本投产比 `1/毛利率` | 直接给安全垫表 + 明确建议先涨 |
| 🟡 **常规** | 后期 + 用户要提利润 / 优化价格 / 优化投产（利润率尚可） | 给安全垫表 + 建议动作，说明"利润健康也可小步试涨" |

**唯一硬性排除**：商品承接有问题（平台 error 级标签 / 转化过低 / 排名过低）——
此时根因在商品侧，**涨价只会放大问题**，先整改，不给涨价建议。

> 常见误区：把"利润低"当成触发门槛。实际上后期优化利润时，**任何毛利率的商品都该看这张表**——
> 高毛利商品涨价的安全垫更小（掉量容忍度低），低毛利商品安全垫更大但更需要涨。

## 2. 计算口径（三张表 + 一条线）

设：单价 `P`、单位成本 `C`、毛利率 `m = (P−C)/P`。

### 2.1 结论表

| 涨价幅度 k | 新单价 | 单件利润 | 利润变化 | 等效营业额/销量增幅 | 最多可掉销量 |
|---|---|---|---|---|---|
| +1% | P×1.01 | — | **+1/m** | +1/m | 1/(m+1) |
| +2% | P×1.02 | — | **+2/m** | +2/m | 2/(m+2) |
| +3% | P×1.03 | — | **+3/m** | +3/m | 3/(m+3) |
| +5% | P×1.05 | — | **+5/m** | +5/m | 5/(m+5) |

> 例（m=10%）：+2% → 利润 **+20%**，等效营业额/销量 **+20%**，最多可掉销量 **16.7%**。

### 2.2 公式

```
利润变化倍数     = 1 + k / m
等效营业额增幅   = k / m                    （等价于"多卖这么多货才换来同等利润"）
最多可掉销量     = k / (m + k)
保本投产比       = 1 / m                    （净ROI 低于此值 = 推广在亏钱）
```

### 2.3 ★ 高频错口径（务必避开）

| 错误写法 | 错在哪 | 正确 |
|---|---|---|
| 保本投产比 = `1/(1−m)` | 那是**成本加成率**（加价率），不是投产比 | 保本投产比 = `1/m` |
| 「涨价 2% 销量掉 2% 就打平」 | 掉量算的是**营业额占比**，不是利润占比 | 掉量上限是 `k/(m+k)`；m=10% 时 2% 涨价能扛 16.7% 掉量 |
| 用「营业额」算利润变化 | 营业额涨 k 但成本不变，利润涨的是 `k/m` | 见 2.2 |

### 2.4 假设（必须随建议一起说明）

- **单位成本不变**、**成本随销量等比例变动**（即没有规模效应、没有阶梯价）。
- 涨价会引发**客户流失、竞品比价**，表中数字只是"安全垫"，不是"一定会发生的结果"。
- 真正的决策点是：**涨价后的实际掉量幅度是否小于表中的安全垫。**

## 3. 怎么取数（三平台）

| 平台 | 商品单价 / 成本 | 投产数据 | 商品阶段 |
|---|---|---|---|
| 拼多多 | `pdd-works --mode sku`（SKU 价）；成本由用户提供 | `pdd-promo --mode goods`（spend/gmv/roi/orderNum） | `pdd-works list` + `pdd-promo goods` 的订单数 |
| 淘宝 | `taobao-promo --mode items`（价格）；成本由用户提供 | `taobao-promo --mode goods` / `sycm.alimama_item_promotion` | 同上 |
| 抖音 | `douyin-shop --mode goods`（priceLower/priceHigher）；成本由用户提供 | `douyin-uni-prom --mode report`（消耗/GMV/ROI） | 同上 |

**成本拿不到时**：只做「相对口径」建议——给定"若毛利率为 X% 则安全垫为 Y"，并明确标注
「单位成本待用户补充，以下按假设毛利率测算」。**不得**默认一个毛利率就下结论。

## 4. 输出格式（固定四段）

```text
【利润与涨价建议】<商品名>

触发条件：商品后期（连续 N 天投产 / 累计 X 单）｜优化诉求：<提利润/优化价格/优化投产>
优先级：🔴 高（毛利率 M% ≤ 20% 或 净ROI R < 保本线 B）/ 🟡 常规（利润率尚可）

涨价幅度    新单价    利润变化    等效营业额/销量    最多可掉销量
+1%         ¥xx       +xx%        +xx%               xx%
+2%         ¥xx       +xx%        +xx%               xx%
+3%         ¥xx       +xx%        +xx%               xx%
+5%         ¥xx       +xx%        +xx%               xx%

建议动作：先涨 <K>%（小步试涨），观察 3~5 天
观察指标：转化率、净ROI、订单数
回滚条件：掉量 > <K>% 对应的安全垫 xx% → 调回原价
假设：单位成本不变、成本随销量等比例变动；掉量受客户流失与竞品比价影响
```

> 🟡 常规优先级时补一句：**利润率健康不等于不该动价格**——安全垫小（掉量容忍度低）恰恰说明
> 试涨要更小步、观察更密。

### 表达约束

- **不得**自行发明阈值（如"毛利率必须降到 15%"）。所有数值来自用户输入或本规则公式。
- 毛利率、成本、单价**必须标注来源**（用户给定 / 平台取数 / 假设值）。
- 平台取到的**指数类指标**（如万相台展现指数）标 Proxy，不当绝对量。
- 没有成本数据时，**不得**写「盈利」「亏损」，只写「投产比 vs 保本线」。

## 5. 小步试涨流程（建议动作）

1. 一次只动**一个商品**、**一个幅度**（建议从 +1%~+2% 起，低毛利商品幅度更小）。
2. 观察 **3~5 个完整自然日**，看三件事：转化率、净ROI、订单数。
3. 判定：
   - 掉量 ≤ 安全垫 → 保留，可进入下一轮小步试涨；
   - 掉量 > 安全垫 → 回滚原价；
   - 转化率掉但 ROI 升 → 中性，继续观察一个周期。
4. 记录每次试涨的价格、日期、掉量、ROI，形成该商品的**价格弹性档案**，下一轮直接用实测弹性
   而不是再用本表的通用安全垫。

## 6. 与其他技能的边界

| 场景 | 走哪条 |
|---|---|
| 平台 error 级标签（转化/排名过低） | 商品侧整改，**不给涨价建议** |
| 新品 / 测款期 / 冷启动期 | 不给涨价建议（还没到后期，价格弹性未稳定） |
| 活动报名锁价期（大促/秒杀/补贴已锁价） | 不给涨价建议（价格改不动） |
| 全店推广结构、低效消耗、预算重分配 | `shop-promotion-diagnosis` / `pdd-promo --mode balance` |
| 单计划预算-ROI 放量测算 | `pdd-promo --mode auto` / `taobao-promo` |
| 货品分层、资源分配 | `product-layering-diagnosis` |
| 价格 A/B 测试设计 | `ab-test-setup`（主指标转化率，护栏毛利/退款率） |
