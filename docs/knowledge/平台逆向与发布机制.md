## 一、淘宝

### 1.1 多属性类目 catId 速查（2026-10-28 实测验证）

见 `dev/README.md`「淘宝多属性类目 catId 速查」表（10 个类目，含属性项/必填数）。
两条反直觉结论：

- **选类目页**右侧「类目必填属性」面板只显示「品牌」1 项 —— 真正的多属性要到**发布页**才渲染，
  所以判断「是否多属性类目」必须看发布页；
- 童装/女装叶子类目必填属性实测 **4~8 项**（不是 10~20），且全部必填、无选填；
  「重要属性 0/N」里的 N 就是必填项数。

### 1.2 选类目三大坑

| 坑 | 事实 |
|---|---|
| 品牌是 readonly select | 触发器是 `.next-select-trigger`，input 只作面板内搜索框；选项**只有 `.options-item`** 可点。`.sell-o-select-options` / `.options-content` 是容器，用 `[class*="option"]` 会误抓容器 → 点不中、按钮永不解禁 |
| 左侧类目树常驻可点 | 约 191 个 `.category-item`，不是级联弹窗；误点会把已选类目改掉（曾把「家居服套装」点成「浴袍」） |
| catId 有只读来源 | 选中类目时 SPA 发 `router/asyncOpt.htm?optType=selectProp&...&catId=<数字>`，**响应体即属性定义** —— 不用进发布页就能拿到 catId + 属性结构 |

### 1.3 发布页三坑

- `scrollIntoView` 是**平滑滚动**：立刻取 `getBoundingClientRect` 拿到的是滚动中坐标
  （实测 y=450，稳定后应 y≈298）→ `mouse.click` 点到别处。必须轮询到坐标稳定再点；
- 「确定」按钮**不在**尺码浮层里（浮层只有「全选/全不选」），是独立浮层的
  `next-btn.submit-btn`；只在尺码 panel 里找 button 永远找不到；
- 点「移除」清理自定义宝贝规格残留，会把已建好的颜色/尺码值**一起删掉**（该做法已废止）。

### 1.4 新版 SKU 面板 + 尺码弹层

`fillSkus` 的「逐个规格值键入」段已按新版面板重写。要点：规格值区是组件化面板，
尺码走弹层勾选，不是纯 input 列表；改版后旧的行号式替换（2540–2661 那段）已失效。

### 1.5 觅千手式「Json/Json2 劫持重放」

淘宝发布页框架把表单 state 赋给 `window.Json` / `Json2`。可在赋值瞬间把本地组装的商品数据
原地 merge 进表单（一次门禁），命中就跳过 DOM 逐格填写，未命中自动降级回 DOM。
主图与详情图可**先用逆向 HTTP 上传传成 `img.alicdn.com` URL**，再随重放注入 ——
与觅千手 v5.61 的「预上传」同一条链路，不再走页面文件控件。
验证脚本已清理，等价能力在 `src/taobao-image-space.ts` / `src/taobao-publish-replay.ts`。

> 觅千手本地包只含**搬家**能力（`pageHooks.js`），**不含**淘宝发品的属性填充。
> 结论细节见 `skills/taobao-publish-mqs/SOURCE.md` §5.3.1。

### 2.1 新版 SKU 页面真实结构（与旧代码假设完全不同）

- 「规格与库存」里**预置了「颜色分类」行**，不需要点「添加规格类型」；颜色值直接在该行输入框填；
- 尺码走「参考分类 / 全部尺码表 / 身高」的 **chips 勾选**（48~175 全在列表里），勾选后自动生成 SKU 行；
- **点「添加规格类型」会弹到顶部搜索框，永远失败** —— 这是旧流程最大的坑。

### 2.2 类目模板决定规格维度，不要自己造

类目模板里带 **preset 维度**（如 `15023 家居袍/睡袍` 内置「颜色分类 × 参考分类」）。
工具会按位置套模板：如果商品 JSON 写的维度名与之不符（例如写成「图案 × 尺码」），
会报 `找不到维度「颜色」`；乱点「添加规格类型」还会被误选成「尺寸」。
**正确做法**：先用 `scripts/pdd-category.mjs template --catId <id> --save` 拉模板，按模板维度组织数据。

### 2.3 价格表是虚拟列表

「价格与库存」表只渲染约 18 行，一滚动/聚焦就重渲染收缩。因此：

- 逐格填价格会在滚动中把值写到别的行（曾 11/30 不一致）；
- 稳妥方案是 **Excel 批量编辑规格**：导出当前规格数据 → 改 xlsx → 导入 → **必须点「确认编辑」**
  → 再导出回读校验；
- 补画行用「滚到中间 + 抖动 + 派发 scroll」，补完**不能滚回顶部**（会再收缩）。

### 2.4 mode2「请求劫持改包」的前提

照抄觅千手 `startFill` 的真实顺序：`fillSkuOnPage`（含 `fillPriceTable`）是**无条件执行**的，
改包只在提交时覆盖。所以 mode2 也必须**先把价格/库存填进页面**，否则：

- 页面校验「请输入第 1 行规格的库存」→ 提交按钮 disabled；
- 拦截不到任何提交请求 → 改包根本不会发生。

### 2.5 采集侧

H5 业务接口需要页面 JS 生成的 `anti_content` 签名，**纯 HTTP 必被拒**，必须驱动浏览器取数。
`search` / `goods` 有账号级频控（常 429 `error_code=40002`），`feed` 稳定可用。

## 三、闲鱼

### 3.1 网页版能发「数字/服务类」商品

结论（2026-10-15 实测）：**能发**。关键不是「网页版不支持」，而是发布页的「分类」是
一个**可选下拉框**，必须手动选到「**其他闲置**」。

- 分类是「自动识别 + 可手动改」，不是只读展示；
- 部分分类被标记「网页版不可发」；
- 实测不同描述触发的候选集里，「**其他闲置**」始终在列 —— 通用的兜底出口。

### 3.2 antd Select 的坑

| 坑 | 事实 |
|---|---|
| 不能只用 `page.click()` | antd Select 需要 `mousedown` + `mouseup` + `click` 三连才触发 `onChange` |
| 不能 evaluate 直接改 value | 分类是 React 受控组件，必须走真实鼠标/键盘事件 |

### 3.3 风险（实测踩过）

- **重复铺货**：同关键词多链接必须换主图换文案，否则判重下架；
- **描述敏感词**：竞品会在描述里写「关键词请用汉字谐音代替」规避；带英文的截图也会被拦。

### 3.4 API 类商品被批量下架的真实根因

2026-11 诊断结论：

| 维度 | 我的账号 | 竞品账号 |
|---|---|---|
| 商品存活 | 8 条**全部被删**（「糟糕！宝贝被删掉了」） | 20 条同品类 **20/20 存活**（含卖 API key、额度、不限量） |
| 账号权重 | 卖出 14 件 / 信用 3 / 粉丝 2（低） | 卖出 16599 件 / 来闲鱼 11 年（高） |
| 类目 | 所有「类目合适」的服务类目网页版全被拦 | — |

→ 不是「API 类不能卖」，而是**低权重账号 + 服务类目**组合被判违规。想卖要先养号权重。

## 四、通用工程约束（踩过的系统级坑）

### 4.1 DSH 沙箱禁止匿名管道

Windows 下 `capture_output=True` / `stdout=PIPE` / `stderr=PIPE` 会被沙箱拦截（EPERM，
**静默返回空**，不报错）。子进程输出一律**重定向到临时文件再读回**。
技能脚本、`dev/` 下的验证脚本都遵循这条。

### 4.2 选择性提交必须真编译一遍

`src/index.ts` 是混写文件，同时 import 多方模块。只在推理上判断「这棵树能编译」不够，
必须把「已提交的树」单独 checkout 到隔离 worktree 里真跑一次编译，才能发现漏掉的依赖。

### 4.3 YAML 块标量解析缺陷（已修）

`wiki-store.ts` 曾自带一个「只读同一行」的 frontmatter 取值函数，注释声称与
`skill-quality` 同一口径但实际不一致 → 遇到 `description: >-` 这类折叠块标量时，
读出来的是**标记符号本身**。回归用例在 `dev/verify-wiki-textpath.mjs`。
