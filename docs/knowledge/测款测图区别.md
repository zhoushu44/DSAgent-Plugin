# 测款和测图的区别

> 测款和测图是新品生命周期里两个关键验证环节，但经常被混为一谈。
> 本文从八个维度深入挖掘两者的本质差异，并补全每个维度的详细操作细节。
> 与「测款测图操作总纲」是对照关系——总纲讲"怎么做"，本文讲"两者到底哪里不同"。

---

## 一句话区别

> **测款验"值不值得做"，测图验"图接不接得住"。**
>
> 测款在上架前，花小钱验证大决策（需求/利润/预算三道门）；
> 测图在上架后有曝光后，用 CTR 验证流量入口承接（一道关 + 五级基准）。

---

## 一、本质差异

| 维度 | 测款 | 测图 |
|---|---|---|
| **回答什么问题** | 这个产品值不值得进货/量产？ | 这张主图能不能接住流量？ |
| **本质** | 花小钱验证大决策 | 用 CTR 验证流量入口承接 |
| **决策性质** | "要不要进入这条链"的门 | 已进入链路后"图行不行"的验证 |
| **失败成本** | 进了货卖不掉=压库存锁死现金 | 图不行开推广=曝光来了点不进来白花钱 |

### 深入：为什么不能混

测款和测图验的东西完全不同：

- **测款验的是"市场层面"**——有没有需求、赚不赚钱、花多少测。这些是**进入决策**的依据，和具体的图无关。
- **测图验的是"执行层面"**——图能不能把曝光变成点击。这是**流量承接**的依据，和市场需不需要无关。

一个产品需求很好、利润很高，但图做得很烂——测款会过（该做），测图不会过（图要换）。
反过来，一个产品图做得很好看 CTR 很高，但没需求没利润——测图会过（图行），测款不会过（不该做）。

**所以两个验证各管一段，不能互相替代。**

---

## 二、时机差异

```
                    测款在这里决断
                        ↓
有产品想法 → [测款] → 进货/上架 → [测图] → 开推广 → 放量
                                        ↑
                                   测图在这里验图
```

| | 测款 | 测图 |
|---|---|---|
| **时机** | 上架**前**（还没花钱进货） | 上架**后**（已经有曝光了） |
| **前提条件** | 有产品想法/样品/供应商报价 | 商品已上架 + 有足够曝光 |
| **如果不过** | 不进货，省钱省时间 | 换图，不开推广 |
| **如果过了** | 进货/上架 | 可以开推广放量 |

### 深入：时序不能颠倒

**不能先测图再测款**——测款不过根本不该进货，进货都没有测什么图。

**不能跳过测款直接进货上架后测图**——需求/利润/预算没验就进货 = 赌，万一需求不存在或利润为负，图做得再好也是亏。

**不能跳过测图直接开推广**——图 CTR 不够，推广引来曝光也点不进来 = 白花钱。

### 深入：测图的前提条件

测图有个前置条件容易被忽略：**要有足够曝光**。

> 没曝光就测图是错的——曝光都没有，CTR 无意义。

测图必须在"流量获取没问题"的前提下做：
- 商品已上架，系统在分配曝光
- 日均曝光 ≥ 500（样本不够 CTR 不可信）
- 如果没曝光 → 先解决曝光（出价/预算/关键词覆盖），不是先测图

---

## 三、验的东西不同

### 测款验三道门（需求 + 利润 + 预算）

| 门 | 验什么 | 怎么验 | 过线 |
|---|---|---|---|
| 需求 | 市场买不买单 | 搜索量/趋势/竞争/痛点，0-100 评分 | ≥70=GO |
| 利润 | 赚不赚钱 | 落地成本+平台费 vs 竞品价 | 毛利≥30%=GO |
| 预算 | 花多少测 | CPC×测试周期×1.5 | 能承受 |

**测款的完整三道门**：

**门一：需求验证（0-100 评分）**

| 信号 | 怎么看 | 甜区 | 数据来源 |
|---|---|---|---|
| 搜索量 | 月搜索量 | 1,000-10,000 | keyword-assistant（国内）/ Jungle Scout（跨境） |
| 趋势方向 | 同比/环比 | 上升或稳定不下降 | keyword-traffic / Google Trends |
| 季节性 | 全年搜索曲线 | 有规律可预期 | keyword-traffic 13 个月趋势 |
| 竞争密度 | 同款卖家数 | 有竞品但不垄断 | market-analysis / 手工搜 |
| 痛点验证 | 竞品差评主题 | 有可解决的痛点 | product-reviews / customer-voice-analyzer |

评分 = 搜索量 20 分 + 趋势 20 分 + 季节 10 分 + 竞争 20 分 + 痛点 30 分。
≥70=GO，50-69=CAUTION，<50=NO-GO。

> 不能只看"市场大"。要看新进入者能拿多少，不是品类老大拿了多少。

**门二：利润验证**

| 成本项 | 怎么算 | 注意 |
|---|---|---|
| 落地成本 | 采购价+头程物流+关税+入库费 | 不是只看工厂报价 |
| 平台费用 | 佣金+FBA/仓储费+支付费 | 按实际费率算 |
| 竞品售价 | 取同款/近款 top10 均价 | 不取最高价（卖不动） |
| 毛利 | 售价-落地成本-平台费用 | 不含推广费 |
| 推广盈亏平衡 | 毛利/(1/ACOS盈亏点) | 推广花多少才不亏 |

毛利率≥30% 且有推广空间=GO，15-30%=CAUTION，<15%=NO-GO。

> "看起来便宜"不等于赚钱。工厂报价$4 的货，加完费用可能是死路。

**门三：预算验证**

| 项 | 怎么算 |
|---|---|
| 关键词 CPC | 查主关键词实际点击单价 |
| 测试周期 | 7-14 天 |
| 日预算 | CPC × 预期点击数/天 × 1.5 |
| 测试总预算 | 日预算 × 测试周期 |
| 盈亏平衡 ACOS | 毛利/售价×100% |
| 目标 ACOS | 盈亏平衡 ACOS × 0.7 |

> 预算算的是"测试成本"不是"排位成本"。不能证明花 X 万排到第 Y 名——任何排位承诺都是未验证假设。

### 测图验一道关（CTR）

| 验什么 | 怎么验 | 过线 |
|---|---|---|
| 主图点击率 | CTR = 点击÷曝光 | ≥行业均值（五级基准取法） |

**CTR 行业均值五级基准**：

| 优先级 | 来源 | 对应技能 | 接线状态 |
|---|---|---|---|
| 1（最优） | 店铺自身历史 CTR | shop-promotion-diagnosis | ✅ 可用 |
| 2 | 同类目竞品 CTR | competitor-strategy-comparison | ✅ 可用 |
| 3 | 行业类目 CTR | industry-data-mcp | ⚠️ MCP 未接线 |
| 4 | 关键词 CTR 趋势 | keyword-traffic + keyword-assistant | ✅ 可用 |
| 5（兜底） | 相对判断 | 人工 | ✅ 无需技能 |

> 不用"我觉得 3% 就行"——不同类目/关键词/位置 CTR 差异极大，通用阈值没意义。

### 深入：为什么测款是三道门而测图是一道关

测款是**进入决策**——要同时回答"有没有需求、赚不赚钱、花多少测"三个问题，任何一个不过都不该进。

测图是**执行验证**——只回答"图能不能把曝光变成点击"一个问题，CTR 是唯一客观指标。

但测图的"一道关"不意味着简单——CTR 基准怎么来就有五级取法，测图方法有 A/B/轮换/竞品对照三种，判断逻辑有三种情况（CTR 低+曝光够 / CTR 低+曝光不够 / CTR 够+后续低）。

## 四、在经营链路里的位置不同

```
流量获取 → 点击响应 → 意向承接 → 成交结果 → 经营质量
              ↑
         测图在这一环

         测款不在这条链里——它在链外，决定"要不要进入这条链"
```

| | 测款 | 测图 |
|---|---|---|
| **在链路的位置** | 链外——决定要不要进入这条链 | 链内第二环：点击响应 |
| **影响什么** | 进入/不进入 | 点击量（曝光×CTR） |
| **和后续环节的关系** | 如果不进入，后续都不存在 | CTR 低→后面所有环节绝对值都小→成交天花板低 |

### 深入：CTR 是放大器

> 曝光量 × CTR = 点击量。CTR 从 2% 提到 4%，等于流量翻倍但不用多花钱。

这是测图为什么重要的根本原因——CTR 是整个链路的**放大器**：
- CTR 低 → 点击少 → 收藏加购少 → 成交少 → 不管后面怎么优化，绝对值都小
- CTR 高 → 点击多 → 后面每个环节的基数都大 → 成交天花板高

测款决定"进不进入链"，测图决定"链的起点放多大"。

---

## 五、数据来源不同

| | 测款的数据 | 测图的数据 |
|---|---|---|
| **主要看** | 市场需求数据 | 自己商品的点击数据 |
| **数据性质** | 市场/行业级（别人的数据推断自己的机会） | 店铺/商品级（自己的真实数据） |
| **数据方向** | 由外向内（看市场→推断自己） | 由内向外（看自己→对标竞品/历史） |

### 测款用的技能（市场层）

| 技能 | 拿什么 | 在测款中的作用 |
|---|---|---|
| keyword-assistant | 搜索量/趋势/点击率/转化率/供需比 | 门一需求验证——搜索量和趋势 |
| keyword-traffic | 13 个月日趋势（展现/点击/CTR/CVR/竞争/均价） | 门一需求验证——季节性和趋势方向 |
| market-analysis | 淘宝搜索页商品数据（价格分布/标题词频/发货地） | 门一需求验证——竞争密度 |
| product-reviews | 淘宝/天猫商品评价 | 门一需求验证——痛点验证 |
| customer-voice-analyzer | 评价转 6 维（人群/场景/优点/痛点/未满足/动机） | 门一需求验证——痛点深度 |
| product-wdj | 商品"问大家"问答 | 门一需求验证——未满足需求信号 |

### 测图用的技能（商品层）

| 技能 | 拿什么 | 在测图中的作用 |
|---|---|---|
| shop-promotion-diagnosis | 自己推广计划 ctr 字段 | 第一级基准——店铺历史 CTR |
| competitor-strategy-comparison | 本品 vs 竞品 ctr | 第二级基准——竞品 CTR |
| industry-data-mcp | 类目 ctr | 第三级基准——行业类目 CTR（未接线） |
| keyword-traffic | 关键词 ctr 趋势 | 第四级基准——关键词 CTR 趋势 |
| keyword-assistant | 关联词 click_rate/free_click_rate | 第四级基准补充 |
| competitor-indicator | 达摩盘 clickRate | 第二级基准补充——达摩盘维度 |
| product-layering-diagnosis | 商品层 ctr | 第一级基准补充——商品维度 |

### 深入：数据性质的根本差异

测款的数据是**市场级的推断**——你在用别人的搜索量、别人的销量、别人的差评来推断"我做能不能成"。
这些数据不是你自己的，有推断误差（你是新手不是老大，要打 0.3-0.5 折）。

测图的数据是**自己商品的真实数据**——CTR 是你自己商品的曝光和点击，是事实不是推断。
基准可能需要对标（竞品/历史），但被验证的 CTR 是你自己的真实值。

**所以测款结论的确定性天然低于测图**——测款是在"猜"市场会不会买单，测图是在"看"图能不能接住流量。

## 六、判断标准不同

| | 测款的判断标准 | 测图的判断标准 |
|---|---|---|
| **核心** | 三道门组合判（需求×利润×预算） | CTR 一道关（≥行业均值） |
| **过线** | 全 GO=量产/有 CAUTION=小批量试/有 NO-GO=不做 | CTR≥行业均值=图 OK/CTR<行业均值×0.7=换图 |
| **不过的后果** | 不进货（省钱省时间） | 换图（不换=开推广白花钱） |
| **决策类型** | 进入/不进入（二元+三档情景） | 换/不换（A/B 测试统计显著） |

### 测款的决策矩阵

| 需求 | 利润 | 预算 | 判决 |
|---|---|---|---|
| GO | GO | 可承受 | **量产** |
| GO | CAUTION | 可承受 | **小批量试**（先进 1/3） |
| GO | NO-GO | — | **不做**（或重谈成本） |
| CAUTION | GO | 可承受 | **小批量试** |
| CAUTION | CAUTION | — | **观望** |
| NO-GO | 任意 | — | **不做** |

### 测图的判断逻辑（三种情况）

| 情况 | 信号 | 判读 | 动作 |
|---|---|---|---|
| CTR 低 + 曝光够 | CTR<行业均值×0.7 | 图承接不足 | 换图测试 |
| CTR 低 + 曝光不够 | 曝光日均<500 | 样本不可信 | 先解决曝光再测图 |
| CTR 够 + 后续低 | CTR≥均值但收藏加购低 | 非图问题 | 查承接不改图 |

### 深入：测款有三档而测图只有两档

测款的"过"有梯度——GO/CAUTION/NO-GO 三档，对应量产/小批量试/不做三种动作。
CAUTION 是"可以做但要有保留"，不是非黑即白。

测图的"过"基本是二元的——CTR 够或不够，换图或不换。
但测图有"CTR 够但后续低"这第三种情况——此时不改图（问题不在图），去查承接。

---

## 七、首批进货量 vs 测图样本量

### 测款的强动作：首批进货量（三档情景）

| 情景 | 算法 | 适用 |
|---|---|---|
| 保守 | 日均预估销量 × 交期 × 0.7 | 资金紧/不确定性高 |
| 基准 | 日均预估销量 × 交期 × 1.0 | 正常 |
| 激进 | 日均预估销量 × 交期 × 1.5 | 有把握/补货周期长 |

日均预估 = 竞品同 BSR 区间销量 × 0.3-0.5 折。

> 红旗：进货量=几年销量 → 月销 30 进 5000 = 14 年库存，锁死现金和仓储。

### 测图的强动作：换图（A/B 测试统计显著）

| 要素 | 要求 |
|---|---|
| 样本量 | 每张图至少 1000 曝光 |
| 测试周期 | 3-7 天（覆盖工作日+周末） |
| 统计显著性 | 差异要够大，2.1% vs 2.0% 不判胜负 |
| 变量控制 | 一次只改一个变量（不同时换图+标题+价格） |

### 深入：两种"强动作"的风险不同

测款的强动作（进货）风险更大——进了货卖不掉是**不可逆**的（钱变库存，库存锁死现金）。
测图的强动作（换图）风险更小——换了图不行可以换回来，是**可逆**的。

所以测款的门槛更高（三道门 + 三档情景 + 红旗检查），测图的门槛相对低（A/B 测试 + 统计显著）。

## 八、最常犯的混淆

| 混淆 | 纠正 |
|---|---|
| "测款就是看销量" | 错。销量是结果，测款验的是需求真实性+利润+预算三件事 |
| "测图就是看图好不好看" | 错。以 CTR 为准，不以审美为准 |
| "测款 ROI 低=该死" | 错。新品样本期 ROI 低正常，看链路通没通 |
| "测款和测图可以同时做" | 不行。测款在上架前，测图在上架后有曝光后 |
| "先测图再测款" | 没意义。测款不过不该进货，进货都没有测什么图 |
| "测款过了就不用测图" | 错。测款过了只说明该做，不说明图行 |
| "测图过了就不用测款" | 错。测图过了只说明图行，不说明该做 |
| "图好看 CTR 就高" | 不一定。图美不美主观，CTR 客观 |
| "新品 ROI 低就停" | 样本期看链路通没通，不看 ROI |

## 九、浓缩对照表

| | 测款 | 测图 |
|---|---|---|
| **时机** | 上架前 | 上架后有曝光 |
| **验什么** | 值不值得做 | 图接不接得住 |
| **几道关** | 三道门（需求/利润/预算） | 一道关（CTR）+ 五级基准 |
| **在链路位置** | 链外（决定进不进） | 链内第二环（点击响应） |
| **数据** | 市场需求数据（推断） | 自己点击数据（事实） |
| **数据方向** | 由外向内 | 由内向外 |
| **过线** | 三门全 GO=量产 | CTR≥行业均值=图 OK |
| **不过** | 不进货 | 换图 |
| **强动作** | 进货（三档情景，不可逆） | 换图（A/B 统计显著，可逆） |
| **失败成本** | 压库存锁死现金 | 曝光了点不进来白花钱 |
| **顺序** | 先 | 后 |

---

## 十、一句话总结

> **测款是"要不要做"的进入决策，测图是"做了之后图行不行"的执行验证。**
>
> **前者省钱（不进货省几万），后者省流量（图不行省推广费）。**
>
> **测款不过不进货，测图不过不开推广。两个都过才能放量。**
